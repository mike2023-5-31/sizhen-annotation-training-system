## 1. 部署概览

系统为前后端分离架构：

- **后端**：FastAPI + Uvicorn（Python 3.10+），依赖 PyTorch/torchvision（训练与推理）、ONNX/ONNX Runtime（模型转换）、SQLAlchemy + SQLite（存储）。
- **前端**：Vue3 + Vite（Node.js），构建产物为纯静态文件。
- **数据**：默认全部落在 `<项目根>/data` 目录下（datasets/ models/ exports/ uploads/ + db.sqlite），可通过环境变量整体迁移（见 4 节）。
- **配置**：后端全部配置 env-driven，代码中无硬编码绝对路径；环境变量未设置时按项目根目录推导默认值。

两种部署场景：本地 Windows 开发机（CPU 即可完成标注与推理，训练降级 CPU）与远程 GPU 服务器（2×RTX 3090，训练加速）。

## 2. 本地 Windows 部署

### 2.1 环境要求

| 依赖 | 要求 |
| --- | --- |
| Python | 3.10+（本机为 CPU 训练即可，`pip install -r` 默认装 CPU 版 torch） |
| Node.js | 18+（含 npm） |
| 浏览器 | Chrome / Edge / Firefox 较新版本 |

### 2.2 后端

在项目根目录执行（PowerShell）：

```powershell
# 1. 创建虚拟环境
python -m venv .venv

# 2. 激活虚拟环境
.\.venv\Scripts\Activate.ps1

# 3. 安装后端依赖
pip install -r backend/requirements.txt
```

依赖清单（`backend/requirements.txt`）：fastapi、uvicorn[standard]、sqlalchemy、pydantic、python-multipart、torch、torchvision、onnx、onnxruntime、scikit-learn、pillow、numpy、pyyaml、websockets、pytest、httpx。

启动后端（**工作目录必须是 `backend/`**）：

```powershell
cd backend
python -m app.migrations # 首次建表；既有库升级前先备份，见 2.5 节
uvicorn app.main:app --port 8000
```

启动后验证：浏览器访问 `http://localhost:8000/api/health`，返回 `{"status":"ok"}` 表示服务存活。业务接口和 `/docs` 需要登录，首次使用先按 §2.6 创建管理员；健康接口不表示账号或数据库迁移已经完成。

### 2.3 前端

在项目根目录执行：

```powershell
cd frontend
npm install
npm run dev
```

前端 dev server 监听 `http://localhost:5173`。Vite 将同源 `/api`（含 `/api/training/ws/training` 的 WebSocket 升级）和 `/static/` 代理到 `http://localhost:8000`。后端地址变化时，在启动 Vite 前设置 `VITE_API_TARGET`，例如 `$env:VITE_API_TARGET='http://127.0.0.1:18112'`。静态部署按 §3.4 配置同源代理。

### 2.4 本地联调验证

1. 打开 `http://localhost:5173/datasets`，登录后进入数据集管理页。
2. 新建数据集 → 打开 `http://localhost:5173/annotate?dataset=<数据集ID>` 标注页。
3. 停止服务：前端 Ctrl+C 结束 vite；后端 Ctrl+C 结束 uvicorn。

### 2.5 v2 增量升级与恢复边界（2026-09-08）

本轮标注保存新增 `annotation_edits` 修改记录表，前后端须同时升级：新接口要求 `expected_revision`，旧页面不携带该字段时返回 428；版本过期返回 409。升级前让使用者保存草稿，停止后端及训练等写入进程，再执行迁移。迁移不会自动在服务启动时运行。

在 `backend/` 下，使用与服务相同的 `DATA_DIR`、`DB_URL` 环境变量执行：

```powershell
..\.venv\Scripts\python.exe -m app.migrations
```

新库创建全部当前表。已有 SQLite 库先检查旧表、数据库完整性和外键，再备份到 `<DATA_DIR>/backups/before-v2-<UTC时间>.sqlite`。必要时迁移会重建数据集和图片表，保留原 ID、关系和历史，并将后续编号推进到已用编号之后，避免删除后复用编号。备份失败时升级停止。以命令成功结束后报告的备份路径作为恢复依据。

该备份只用于**数据库结构升级回退**，不包含图片、XML、自定义模型、权重及浏览器草稿。升级前应另行保存停止写入时的整个数据目录，以及配置中放在数据目录外的模型/导出等目录。尚未完成整个平台的一键备份与恢复功能。

恢复演练应先在独立目录进行：使用 SQLite 备份接口将备份复制到新的数据库文件，检查 `PRAGMA integrity_check` 返回 `ok`，核对数据集与图片记录，再配套恢复同一备份时点的图片/XML及兼容代码。不要把只有旧数据库的备份覆盖到仍在运行、已经产生新标注的数据目录。本轮自动化测试已在临时库验证旧记录保留和数据库备份恢复；用户真实数据恢复、整套文件一致性及机器人环境仍未验收。

### 2.6 独立账号与会话（2026-09-08）

本版默认要求登录，没有匿名业务模式或内置默认密码。先停止旧后端、备份并运行 §2.5 迁移以创建 `users`、`login_sessions`（及尚不存在的 `annotation_edits`）表，然后在 `backend/` 下创建第一个管理员。密码交互输入，不放入命令行参数或代码库：

```powershell
..\.venv\Scripts\python.exe -m app.accounts create team-admin --role admin
```

管理员登录后，在“账号”页创建其他三名成员。也可以使用相同 CLI 创建成员（省略 `--role admin`）。管理员忘记密码时，运维人员在服务器本地执行 `python -m app.accounts reset-password team-admin`，会撤销该账号全部登录。账号名为 3–64 位小写字母/数字/`_.-`，密码为 12–128 字符；错误密码连续五次会锁定账号十五分钟，管理员重置密码可清除锁定。不预先创建实际人员账号，避免擅自指定身份与密码。

| 配置 | 默认值 | 用法 |
| --- | --- | --- |
| `COOKIE_SECURE` | `true` | 共享部署使用 HTTPS；仅本机 HTTP 开发可设 `false` |
| `SESSION_SECONDS` | `28800` | 八小时绝对会话期限；退出、重置密码或停用会撤销会话 |
| `AUTH_ALLOWED_ORIGINS` | `http://localhost:5173,http://127.0.0.1:5173` | 登录与 WebSocket 允许的浏览器来源，逗号分隔，填写真实访问地址，不能用 `*` |
| `VITE_API_TARGET` | `http://localhost:8000` | Vite 同源代理的后端地址，启动前设置 |

纯本地开发示例（启动后端前设置）：

```powershell
$env:COOKIE_SECURE='false'
$env:AUTH_ALLOWED_ORIGINS='http://localhost:5173,http://127.0.0.1:5173'
```

会话保存在 HttpOnly、SameSite=Strict Cookie，数据库只存随机会话令牌的摘要；前端通过 `/api/auth/me` 获取当前身份与 CSRF 值，写操作携带 `X-CSRF-Token`。登录请求另带 `X-Requested-With: XMLHttpRequest`。Python/脚本客户端应使用同一个 Cookie 会话登录后再访问业务 API，不能继续匿名调用。生产反向代理应把前端和 `/api`、WebSocket 放在同一来源；不支持把带凭证 API 任意改为跨域地址后仍假定所有图片和下载入口可用。

认证覆盖业务 API、`/static`、下载及训练 WebSocket；管理员可以管理账号及上传可执行自定义模型，成员没有这些权限。**当前登录成员仍共用现有数据/训练工作空间，尚未实现按项目成员分配数据和模型访问范围**，因此 NFR-02 仅部分完成，不能据此验收多项目隔离。

标注草稿按用户 ID 使用新的本地存储命名空间。旧版 `sizhen.annotation.draft.v2:` 草稿缺少操作者信息，保留但不自动归给任意账号；升级前先在旧版保存未提交草稿。已登录账号之间的草稿不会相互加载；同浏览器跨标签页切换账号后，旧页面保存会被拒绝，回到原账号重新加载可恢复其草稿。本地草稿隔离不等于对共享操作系统账号的存储加密。

实现依据：[OWASP 密码存储](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)、[OWASP 会话管理](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)（2026-09-08 核对）。当前密码采用 PBKDF2-HMAC-SHA256、600000 次迭代和独立随机盐；这不代表任何合规认证。

### 3.2 创建独立 conda 环境（勿复用 sparsesurf）

本系统使用**独立的新环境 `sizhen`**，不复用 `sparsesurf` 环境（避免依赖冲突）。

```bash
# 1. 创建独立环境（Python 3.10）

```

> ⚠️ 顺序说明：`requirements.txt` 中的 `torch`/`torchvision` 若先由 pip 解析，可能装成 CPU 版。先装 cu118 版（已满足版本约束，pip 不会再换源重装）。装完后可用
> `python -c "import torch; print(torch.cuda.is_available(), torch.cuda.device_count())"`
> 确认，期望输出 `True 2`。

模型目录仅放本系统生成或经运维核验来源的存档。限制权重反序列化仍依赖 PyTorch 的安全更新，部署验收时记录并核对实际 PyTorch、CUDA 和驱动版本。[PyTorch 反序列化说明](https://docs.pytorch.org/docs/stable/notes/serialization) · [安全公告](https://github.com/pytorch/pytorch/security/advisories/GHSA-63cw-57p8-fm3p)

### 3.3 启动后端

```bash

```

### 3.4 前端构建与静态托管

```bash
cd ~/sizhen-annotation-training-system/frontend
npm install
npm run build          # 产物在 frontend/dist/
```

共享部署用 Nginx 同源托管。将以下配置放在 `http` 块内，替换域名、证书和构建产物路径。后端设置 `COOKIE_SECURE=true` 和对应的 `AUTH_ALLOWED_ORIGINS`。

```nginx
map $http_upgrade $sizhen_connection {
    default upgrade;
    ''      close;
}

# http{} 级别：按来源 IP 限流（与应用内账号锁定互补，防跨账号撞库）
limit_req_zone $binary_remote_addr zone=sizhen_login:10m rate=6r/m;
limit_req_zone $binary_remote_addr zone=sizhen_api:10m rate=20r/s;

server {
    listen 443 ssl;
    server_name sizhen.example.internal;
    ssl_certificate /path/to/fullchain.pem;
    ssl_certificate_key /path/to/privkey.pem;

    root /home/ccl/sizhen-annotation-training-system/frontend/dist;
    index index.html;
    client_max_body_size 1m;
    proxy_http_version 1.1;
    proxy_set_header Host $http_host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection $sizhen_connection;

    location = /api/auth/login {
        limit_req zone=sizhen_login burst=5 nodelay;
        proxy_pass http://127.0.0.1:8000;
    }
    location ~ ^/api/datasets/[0-9]+/import/?$ {
        limit_req zone=sizhen_api burst=40 nodelay;
        client_max_body_size 257m;
        proxy_pass http://127.0.0.1:8000;
    }
    location = /api/training/ws/training {
        proxy_read_timeout 90s;
        proxy_pass http://127.0.0.1:8000;
    }
    location /api/ {
        limit_req zone=sizhen_api burst=40 nodelay;
        proxy_pass http://127.0.0.1:8000;
    }
    location /static/ {
        proxy_pass http://127.0.0.1:8000;
    }
    location ~ ^/(docs|openapi\.json)$ {
        proxy_pass http://127.0.0.1:8000;
    }
    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

默认 ZIP 文件上限为 256 MiB，代理为 multipart 边界预留空间。调整 `MAX_UPLOAD_BYTES` 时同步调整该路由的代理上限。自定义模型 Python 源码的应用上限为 512 KiB。应用继续校验上传文件和 ZIP 展开限制。`limit_req` 超限返回 429；登录限流与账号 5 次失败锁定互补。部署时执行 `nginx -t`，再按 §4 检查实际站点。[Nginx 请求体配置](https://nginx.org/en/docs/http/ngx_http_core_module.html#client_max_body_size) [Nginx 限流](https://nginx.org/en/docs/http/ngx_http_limit_req_module.html)

### 3.5 环境变量配置

后端全部配置 env-driven（`backend/app/config.py`），未设置时自动推导默认值（`<root>` 为项目根目录）。相对路径按项目根解析。

| 环境变量 | 作用 | 默认值 |
| --- | --- | --- |
| `DATA_DIR` | 数据根目录（下含 datasets/ models/ exports/ uploads/） | `<root>/data` |
| `MODEL_DIR` | 模型保存目录（checkpoint、ONNX 产物） | `<DATA_DIR>/models` |
| `EXPORT_DIR` | 导出目录 | `<DATA_DIR>/exports` |
| `UPLOAD_DIR` | ZIP 导入暂存目录 | `<DATA_DIR>/uploads` |
| `DB_URL` | SQLAlchemy 数据库 URL | `sqlite:///<root>/data/db.sqlite` |
| `LABELS_PATH` | 标签体系 YAML 路径 | `<root>/backend/config/labels.yaml` |
| `CORS_ORIGINS` | 逗号分隔的允许跨域来源 | `*`（开发期任意来源） |

设置示例（Linux，启动前 export；Windows 用 `$env:` 或系统环境变量）：

```bash
export DATA_DIR=/home/ccl/sizhen-data
export MODEL_DIR=/home/ccl/sizhen-data/models
export EXPORT_DIR=/home/ccl/sizhen-data/exports
export DB_URL="sqlite:////home/ccl/sizhen-data/db.sqlite"
export LABELS_PATH=/home/ccl/sizhen-annotation-training-system/backend/config/labels.yaml
export CORS_ORIGINS="http://59.77.6.21:5173,http://59.77.6.21"
```

注意事项：

- 生产环境建议用 `CORS_ORIGINS` 收紧允许来源（默认 `*` 仅适合开发期）。
- `DB_URL` 为 SQLite 绝对路径时注意 URL 形式：`sqlite:////abs/path/db.sqlite`（四个斜杠 = `sqlite://` + 绝对路径 `/abs/...`）。
- 修改 `labels.yaml` 标签后需重启后端生效。
- 首次启动后端会自动创建数据目录树，无需手动建目录。

### 3.6 GPU 能力验证（冒烟）

远程 GPU 的 CUDA 可见性、FP16 混合精度、DataParallel 双卡路径需按 `docs/GPU_SMOKE.md` 清单人工验证（三项全 PASS 才算 GPU 真实路径就绪）：

| 项 | PASS 标准 |
| --- | --- |
| CUDA 可见性 | `torch.cuda.is_available()` 为 True 且 `device_count >= 2` |

## 5. 常见问题

| 问题 | 处理 |
| --- | --- |
| `uvicorn` 命令找不到 | 虚拟环境/conda 环境未激活，或 `pip install -r backend/requirements.txt` 未执行。 |
| 启动报 `ModuleNotFoundError: app` | uvicorn 工作目录不对，必须在 `backend/` 目录下执行 `uvicorn app.main:app`。 |
| 前端页面能开但请求失败 | 后端未启动，或后端端口不是 8000（检查 `frontend/vite.config.js` 代理配置）。 |
| 服务器训练用 CPU 而不是 GPU | torch 装成了 CPU 版，按 3.2 节重装 cu118 版并确认 `torch.cuda.is_available()` 为 True。 |
| 站点登录或 WebSocket 失败 | 核对实际 HTTPS 域名、`AUTH_ALLOWED_ORIGINS`、代理请求头及 §3.4 路由。 |
| 导入返回 413 | 核对 ZIP 文件上限、代理请求体上限和 multipart 开销。 |
| SQLite 报 database is locked | 确认后端仅有一个工作进程，排查并行迁移和其他持有写锁的程序。 |
