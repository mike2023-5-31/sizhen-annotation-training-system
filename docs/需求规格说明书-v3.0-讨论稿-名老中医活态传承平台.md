## 1. 定位与范围

### 1.1 平台定位

本系统应支持**构建完整复现名老中医药专家临床思维与操作技能的 AI 数字人模型**，实现思维数字化、诊断具象化、操作可复制。平台整体由三层构成：

| 层 | 内容 | 对应既有/新增 |
| --- | --- | --- |
| 底座层（既有，保留） | 数据采集导入、治理、标注、版本、训练、评估、发布、部署、回流；含四诊模板与机器人操作视觉模板 | v2.0 讨论稿 §1—§13 全部内容，编号不变 |
| 传承应用层（新增） | 经验采集（含病案/视频/音频/四诊）、诊疗思维记录、经验展示、经验学习 | 本稿 §4.1—§4.4 |
| 数字人层（新增） | 名老中医数字人模型训练、中医问诊路径学习、AI 数字人思维模拟/问答 | 本稿 §4.5—§4.7 |
| 数据管理层（新增+扩展） | 分类、归档、查询、共享、批量、权限 | 本稿 §4.8，扩展底座既有数据管理 |

底座层要求在本稿中**不再重复列表**：v2.0 讨论稿（含 21 条原始要求、REQ-6.22—6.35、ROB-01—12、DATA-01—05、NFR-01—13、AC-01—15、DEC-01—09）在范围扩展后**全部继续有效**，除非本稿显式修订。

### 1.2 范围边界

- 本平台是「采集 → 治理 → 结构化知识 → 传承学习 → 数字人训练与模拟」的完整闭环；标注训练底座是其中一环，不是全部。
- 本稿不把任何「demo 或原型页面」当作正式验收；所有功能要求以 2.1—2.8 的可观察结果为准。
- **AI 数字人不替代真实名老中医的医疗行为**：本稿所有面向患者/学员的生成内容须有清晰来源标注与免责边界；该边界为 P0 约束，详见 §5.5、§5.7 与 §6。
- 机器人视觉专项（ROB-01—12）属于底座既有范围，本稿不展开、不删除。

### 1.3 优先级与确认规则

沿用 v2.0 规则：P0=真实交付前必须完成；P1=首期持续使用所需；P2=后续扩展。本稿新增项的优先级均为**建议值**，须经业务确认。**待确认项一律不视为用户承诺**；涉及未知业务语义的任务先做接口与模板设计，语义确定后再编码。

## 3. 角色与权限扩展

### 3.1 新增角色（叠加于 v2 §3.1 底座角色之上）

| 角色 | 职责（建议） | 待确认/约束 |
| --- | --- | --- |
| 名老中医（本人或其授权代表） | 提供真实医案、参与入模授权、确认思维记录与辨证/方药偏好口径 | 名单与授权方式待确认；本人账号或专属授权人 |
| 录入/摄制人员 | 病案文字录入、图片/视频导入、高清拍摄上传、音频录制与上传 | 与底座「项目成员」是否同账号体系待定 |
| 导师 | 对学员思维记录标注补充与修正（2.2）、对学员心得点评（2.4） | 导师与底座「标签维护职责/复核」的关系、是否属于「专家复核」待 DEC |
| 学员 | 视频学习、病案研读、提交心得、查询学习记录、标记重点、收藏（2.4） | 学员是否为不限人数外部身份；与四名底座用户关系待 DEC |
| 传承平台管理员 | 名老中医档案、医案范围、内容发布、角色授权、归档/共享审批 | 与底座管理员合并或分设待定 |

### 3.2 权限与既有“无专家复核”原则的关系

v2.0 依据用户反馈设定底座**默认不设标注提交与专家复核**。本稿 2.2「导师对思维记录标注补充和修正完善」与 2.4「导师点评」属于**传承内容与学习环节**的导师行为，**不等同于底座标注训练环节重新引入专家复核门槛**。两者是否需要在同一账号体系下分别授权、以及导师能否被底座训练准入引用，列为 DEC-10。

## 4. 功能需求（新增，2.1—2.8 展开）

> 编号约定：`REQ-8.x.y` 对应来源 2.x 的第 y 条细化。优先级为建议值。每条含验收要点；凡标注「待确认」之处须冻结后才进入编码或正式验收。

### 4.1 经验采集（来源 2.1）

| 编号/优先级 | 要求 | 验收要点 |
| --- | --- | --- |
| REQ-8.1.1 / P0 | 病案录入支持文字、图片、视频导入；支持同一医案下多模态材料关联 | 文字病案可建可存可查；图片/视频正确关联到医案且不丢元数据；混合材料医案端到端可浏览 |
| REQ-8.1.2 / P0 | 视频拍摄与上传：支持高清拍摄/文件上传，登记分辨率、帧率、时长、编码、设备与采集时间 | 上传后可播放；上传过程失败可重试且不产生半截资产；元数据齐全可追溯 |
| REQ-8.1.3 / P0 | 音频录制与上传：支持录音、降噪处理、自动转写、上传；登记采样率、声道、时长、录音设备与噪声等级 | 录制→降噪→转写→上传全流程可用；转写文本与音频可对位回放；降噪/转写算法版本记录（待确认：引擎与语言模型） |
| REQ-8.1.4 / P0 | 四诊数据采集接入底座既有采集/导入能力（舌/面/脉/声音模板），供医案与训练共用 | 与底座数据语义一致；医案内四诊材料可被标注/训练引用；不重复造四诊数据定义 |
| REQ-8.1.5 / P0 | 支持多格式数据导入与批量上传；未知/不支持格式返回明确清单，不静默丢弃 | 批量导入总数=成功+失败+跳过且可核对；格式支持表集中声明并可在导入前查看 |
| REQ-8.1.6 / P1 | 敏感内容处理：医案含患者信息时按最小化与脱敏原则存储与展示 | 身份字段脱敏；导出/展示遵循授权；与 NFR-03 一致 |

### 4.2 中医诊断思维记录（来源 2.2）

| 编号/优先级 | 要求 | 验收要点 |

| REQ-8.2.2 / P0 | 诊断推理过程的逻辑链条可视化展示（如节点图/步骤流） | 从记录生成可读的推理链视图；节点跳转/回看一致；视图可导出（P1） |

### 4.5 数字人模型训练（来源 2.5，▲ 核心）

| 编号/优先级 | 要求 | 验收要点 |
| --- | --- | --- |
| REQ-8.5.1 / P0 | 构建不少于 3 名核心名老中医的 AI 数字人模型；每名数字人**基于该名老中医的真实临床医案数据**训练 | 每名数字人可列出其训练医案的数据版本与样本量；不得用其他专家或合成数据冒充（待确认：3 名人员名单、数据规模与授权） |

| REQ-8.5.6 / 待确认 | 数字人底层技术路线（基座模型、微调/增量训练框架、是否本地部署、许可证） | 技术选型决策前不做实现承诺；涉及外部大模型时遵守 NFR-05 模型安全 |

### 4.6 中医问诊路径学习（来源 2.6）

| 编号/优先级 | 要求 | 验收要点 |

| REQ-8.6.1 / P0 | 基于当前问诊进度与已获取症状信息，实时分析问诊完整度 | 完整度计算有明确定义与可解释依据（问题覆盖/关键证素是否获取）；口径待医学确认 |

| REQ-8.8.1 / P0 | 数据分类、归档、查询、共享、删除 | 分类/归档/共享规则可配置；删除遵循底座回收站与引用保护规则 |
| REQ-8.8.2 / P0 | 支持数据批量处理 | 批量操作有确认、进度、失败清单与可重试性 |
| REQ-8.8.3 / P0 | 数据权限控制保障数据安全 | 医案/患者敏感数据、名老中医档案、未发布经验按角色授权访问；越权读写被拒绝并留痕 |
| REQ-8.8.4 / P1 | 数据规范可用：统一字段、校验、去重与质量状态 | 数据体检报告可查；不规范的旧数据不自动升级为可用 |

## 5. 复用映射与边界（与 v2 底座的关系）

| 本稿范围 | 主要复用 v2 能力 | 需新增/改造 | 冲突或边界 |
| --- | --- | --- | --- |

| 2.1 四诊采集 | 四诊模板、标注、XML/schema | 医案内四诊材料引用；视频/音频作为新模态进模板 | 沿用 DATA-01—05 语义，不得把视频当单图处理 |
| 2.2 思维记录 | 标注修订、rev、审计（6.4/§7） | 链式结构化记录、导师修订、推理链可视化 | 记录对象是「诊疗思维」不是图片标签；schema 全新 |
| 2.4 学习闭环 | 账号与角色基础（NFR-02） | 学员/导师角色、心得/点评/收藏对象 | 导师点评与「无专家复核」原则边界见 DEC-10 |
| 2.5/2.7 数字人 | 数据版本、run_id 追溯、评估/发布（REQ-6.27—6.29、NFR-12） | 数字人任务产线、风格画像、模拟/问答服务 | 底座 ResNet/检测训练器不能直接承担数字人训练 |
| 2.6 问诊路径 | （无直接复用） | 路径模板、完整度引擎、推荐问题 | 全新领域；医学规则须专家确认 |

## 7. 验收场景（新增 AC-16 起）

| 用例 | 输入/操作 | 必须观察到的结果 | 追踪 |
| --- | --- | --- | --- |
| AC-16 | 含文字病案、图片、视频、音频的医案批量录入并关联 | 各模态资产齐全且关联正确；失败条目逐条可查 | 2.1、REQ-8.1.1/1.5 |
| AC-17 | 音频录制→降噪→转写→上传→回放对位 | 转写文本与音频对位；引擎版本被记录 | REQ-8.1.3 |
| AC-18 | 为一条真实医案建立完整诊疗思维链（四诊→辨证→治则→方剂→配伍）并可视化 | 链完整可读；导师修订可区分、可回溯 | 2.2、REQ-8.2.1—8.2.3 |
| AC-19 | 按名老中医/疾病/技术分类浏览、关键词+疾病+专家组合查询 | 分类与查询结果正确；视频倍速/暂停/全屏可用 | 2.3 |
| AC-20 | 学员学习→标记重点→收藏→提交心得→导师点评→查询学习记录 | 全闭环完成且按学员隔离 | 2.4 |
| AC-21 | 3 名名老中医各自基于自身真实医案构建数字人并核对风格画像 | 每名数字人数据版本/样本量可查；辨证/方药偏好分布来自其本人医案 | 2.5、REQ-8.5.1/8.5.2 |
| AC-22 | 新增医案进入新版本并触发数字人再训练 | 新版本训练可追溯；旧版本仍可回看 | REQ-8.5.3 |
| AC-23 | 模拟一次四诊问诊，检查问诊完整度与下一步追问提示 | 完整度可解释；提示与已答症状一致；遗漏项可追模板 | 2.6 |
| AC-24 | 分别调用 3 名数字人辨证论治与问答，并检验无依据诊疗内容 | 专家间不串库；输出带模拟/免责标识；无来源承诺被拒绝 | 2.7、REQ-8.7.1—8.7.4 |
| AC-25 | 学员尝试越权读取患者敏感医案或未授权名老中医档案 | 拒绝访问并留痕；脱敏生效 | 2.8、REQ-8.8.3、NFR-15/16 |
| AC-26 | 对医案/经验执行分类、归档、共享、批量删除 | 批量有确认与失败清单；删除遵循引用保护与回收站 | REQ-8.8.1/8.8.2 |

验收证据规范沿用 v2：执行时间、执行人、代码/数据版本、环境、输入、预期、实际与产物路径；未执行写「待验证」。

## 8. 分期与实施顺序（建议）

| 阶段 | 交付 | 退出条件 |
| --- | --- | --- |
| A：底座继续冻结（v2 既定） | 底座数据/训练/机器人专项按 v2 顺序执行 | v2 AC-01—15 通过 |
| B：医案与多模态采集 | 医案模型、视频/音频资产、批量导入、四诊引用 | AC-16/17 通过；患者数据边界确认 |
| C：思维记录与展示学习 | 思维链 schema、可视化、导师修订；分类展示、查询、播放、心得点评 | AC-18—20 通过；医学词表经专家确认 |
| D：数字人产线 | 3 名专家数据版本、风格画像、再训练、模拟问答、安全边界 | AC-21—24 通过；名单/授权/技术路线确认 |
