## 1. 引言

### 1.1 编写目的

本文档是「四诊数据标注与AI模型训练系统」的需求规格说明书。目的：在原始要求书基础上，将 21 条功能需求逐条展开为可验证、可验收的需求条目（编号 REQ-6.N-M），并补充非功能需求、技术栈、数据流、标签体系、XML Schema、数据库 Schema、约束与假设。本文档回答「系统要做什么、做到什么程度」，不涉及实现方案与内部结构（由概要设计、详细设计文档承担）。

### 1.2 项目背景

四诊（望舌、望面、切脉、闻声音）是中医诊断的基础环节。本系统面向四诊影像与声音数据的标注、管理、模型训练与推理部署场景：用户导入四诊数据（图片与标注 XML），在网页上快速浏览、打标签并导出标注成果；用标注数据训练分类模型，实时监控训练过程，评估模型效果，批量推理生成预标注，并将模型转换为 ONNX 格式用于部署。

### 1.3 术语与缩略语

| 术语 | 说明 |
| --- | --- |
| 四诊 | 舌诊、面诊、脉诊、闻诊（声音），本系统的 4 个并列类别 |
| 数据集 | 一组记录（图片 + 对应标注 XML）的逻辑集合 |
| 内置库 | 系统内维护的四诊数据总库，由 ZIP 导入填充，可从中按时间范围拉取记录到数据集 |
| 标签体系（taxonomy） | 四类并列 + 每类子标签的配置，是标注、训练、预标注的共同依据 |
| 标注 XML | 与图片同名、描述该图标签与质量的 XML 文件 |
| 预标注 | 由模型推理结果自动生成的标注，confidence 为预测概率 |
| checkpoint（训练存档） | 训练过程产物，含模型参数、优化器状态、已训练轮数、最佳指标追踪 |
| ONNX | 开放神经网络交换格式，用于模型部署 |
| 宏平均准确率 | 对某个分类头，其各子标签类别准确率的算术平均 |

## 2. 总体描述

### 2.1 产品描述

单机 Web 系统，前后端分离架构，面向单人标注与训练工作流。主要功能链：数据集管理 → 数据导入 → 标注 → 导出 → 训练 → 评估 → 推理 → ONNX 转换与下载。

### 2.2 系统范围

- **数据管理**：数据集创建/删除/重命名/列表，ZIP 导入，内置库按时间范围拉取（含质量过滤）。
- **标注**：图片浏览检索、结构化标签标注、自动保存、数据删除、导出 ZIP。
- **训练**：混合数据集训练、模型架构选择（ResNet18/50/自定义）、GPU/CPU 与 FP16、超参数可调、数据增强、断点续训、实时监控、评估可视化、模型加载/保存。
- **推理**：推理数据集选择、批量预测、结果表格、预标注 XML 生成。
- **模型转换**：PyTorch 到 ONNX 一键转换、精度对比、一键下载。

### 2.3 非目标（不在本系统范围内）

- 不做目标检测/分割（无 bbox、掩码语义），本系统为分类系统，XML 不含检测字段。
- 不做用户登录、权限管理、多人协作。
- 不做多机分布式训练，仅单机单卡/多卡。
- 不内置真实四诊数据，数据由用户导入。
- 不修改、不迁移任何既有工程。

### 2.4 用户特征

使用者为具备基本计算机操作能力的研究人员或学生，需熟悉四诊标签含义。系统应提供清晰的操作提示、明确的状态反馈（当前位置、进度、错误原因）与可读的错误信息。

### 2.5 运行环境

- 使用环境：Windows 10/11（本地开发与使用）或 Ubuntu（GPU 服务器）。
- 浏览器：现代浏览器（Chrome/Edge/Firefox 较新版本）。
- 硬件：CPU 即可完成标注与推理；训练无 GPU 时以 CPU 降级运行，有 NVIDIA GPU 时可加速训练。

## 4. 数据流

主链路：**导入 → 标注 → 导出 → 训练 → 推理 → ONNX**。

1. **导入**：用户上传 ZIP（图片 + 标注 XML）自动解压入库；内置库同时被填充，可再按时间范围拉取到数据集。
2. **标注**：浏览/检索图片，通过标注面板选择标签，标签变更自动写入 XML。
3. **导出**：数据集整体导出为 ZIP（图片 + XML），该 ZIP 可再次导入，实现往返。
4. **训练**：选定主数据集 + 叠加数据集构建训练数据，在 GPU/CPU 上训练，实时监控指标，产出最佳模型与评估结果（混淆矩阵、ROC）。
5. **推理**：选定数据集与模型，批量推理得到每图每类预测（子标签 + 概率），可生成预标注 XML。
6. **ONNX**：训练产物一键转换为 ONNX，与 PyTorch 输出对比校验精度，通过后下载交付。

文字示意：

```
ZIP 上传 ──→ 解压识别 ──→ 内置库 ──→ 按时间范围拉取 ──┐
                                                    ├──→ 数据集 ──→ 标注(自动写 XML) ──→ 导出 ZIP
                                                       （导出后可再次导入，往返一致）
数据集（主 + 叠加） ──→ 训练（GPU/CPU/FP16/断点续训） ──→ 最佳模型 + 评估（混淆矩阵/ROC）
模型 + 推理数据集 ──→ 批量预测（各类概率） ──→ 结果表格 + 预标注 XML
最佳模型 ──→ ONNX 转换 ──→ 精度对比（每头 max abs diff < 1e-3） ──→ 下载
```

## 5. 数据接口规范

### 5.1 标签体系

- 四类并列：**舌、面、脉、声音**。
- 每类含若干子标签，每类的第一项固定为「正常/无」默认类。
- 每类最多选一个子标签；一张图片可含 0 到 4 个 label（每类至多 1 个）。
- 子标签当前为占位默认值，可通过配置文件修改为真实标签（见 8 节约束 C-1）。
- 标签体系是标注界面、训练建码、预标注生成的共同依据；混合训练时，主数据集与全部叠加数据集的标签体系必须一致。

### 5.2 标注文件 XML Schema

每张图片配一个同名 XML 标注文件，结构如下：

```xml
<annotation>
  <folder>数据集名</folder>
  <filename>a.jpg</filename>
  <path>图片存储路径</path>
  <size>
    <width>640</width>
    <height>480</height>
    <depth>3</depth>
  </size>
  <quality>合格</quality>
  <labels>
    <label>
      <category>舌</category>
      <name>舌苔黄</name>
      <confidence>1.0</confidence>
    </label>
  </labels>
</annotation>
```

字段说明：

| 字段 | 类型 | 取值/说明 |
| --- | --- | --- |
| annotation | 根元素 | 每张图片一个 |
| folder | string | 所属数据集名 |
| filename | string | 图片文件名 |
| path | string | 图片存储路径 |
| size/width | int | 图片宽（像素） |
| size/height | int | 图片高（像素） |
| size/depth | int | 通道数 |
| quality | enum | 合格 / 不合格 / 空字符串（未标记） |
| labels | 容器 | 0 到 4 个 label（每类别至多 1 个） |
| label/category | enum | 舌 / 面 / 脉 / 声音 |
| label/name | string | 子标签名，必须在标签体系内 |
| label/confidence | float | 人工标注 = 1.0；预标注 = 模型预测概率（0 到 1） |

约束：

- 标签与质量以 XML 为唯一真相源，数据库仅镜像 quality 字段供 6.2 快速过滤，不在数据库存标签，避免双源漂移。
- XML 写入采用原子写（临时文件 + 替换），保证快速连续修改或中断时不产生损坏/半截文件。
- 导出 ZIP 再导入后，标签与 quality 与原数据逐字节一致（往返保真）。

### 5.3 数据库 Schema

SQLite，共 2 张表。数据库不存标签（标签唯一真相源在 XML）。

**Dataset 表**：

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | integer | 主键，自增 | 数据集唯一标识 |
| name | string | 唯一，非空 | 数据集名 |
| created_at | datetime | | 创建时间 |
| updated_at | datetime | | 更新时间 |

**Record 表**：

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | integer | 主键，自增 | 记录唯一标识 |
| dataset_id | integer | 外键 → Dataset.id | 所属数据集 |
| filename | string | 非空 | 图片文件名 |
| image_path | string | 非空 | 图片存储路径 |
| timestamp | datetime | 可空 | 采集时间，用于按时间范围拉取 |
| quality | string | 可空 | 镜像 XML quality（合格/不合格/空） |
| created_at | datetime | | 记录创建时间 |

语义：

- 内置库与普通数据集共用 Record 表，ZIP 导入的数据同时写入内置库对应的记录。
- 从内置库拉取到数据集 = 复制记录行（新 dataset_id 关联），不移动、不删除源记录，内置库天然不可变。
- 删除数据集内记录 = 硬删除记录行与对应 XML；内置库中的源记录不受影响（无软删除标记）。

## 6. 功能需求

> 每条功能需求按「需求描述 + 可验收条目（REQ-6.N-M）+ 验收标准」展开。REQ-6.N-M 即后续测试用例的追踪依据。

### 6.1 数据集管理

**需求描述**：用户可创建、删除、重命名数据集；系统以列表展示全部数据集并提供下拉选择，供标注、训练、推理等功能页选用当前数据集。

**可验收条目**：

- REQ-6.1-1 创建：输入名称即可创建数据集；名称为空或与已有数据集重名时，系统明确报错（如 409/400 与可读提示）。
- REQ-6.1-2 列表：系统以表格列出全部数据集及其基本信息。
- REQ-6.1-3 重命名：用户可修改数据集名称，改名即时生效并反映在列表与下拉框中。
- REQ-6.1-4 删除：用户可删除数据集，删除前需二次确认；删除仅移除数据集内记录与关联标注文件，不物理删除磁盘图片（删除前系统提示可先导出备份）。
- REQ-6.1-5 下拉选择：标注、训练、推理等页面可通过下拉列表选择数据集。

**验收标准**：对数据集执行创建、列表、重命名、删除四类操作全部成功；重名创建被拒绝且提示明确。

### 6.2 数据导入

**需求描述**：两条导入渠道。

- **ZIP 上传**：用户上传 ZIP 包，系统自动解压并识别 jpg/jpeg/png/bmp/gif 图片，每张图片与其同名 XML 标注文件配对导入；导入过程提供进度反馈，结束后返回汇总（导入数、跳过数、错误列表）。
- **内置库拉取**：从内置数据库按时间范围拉取四诊数据进入数据集，并过滤「质量合格」图片。

**可验收条目**：

- REQ-6.2-1 解压识别：ZIP 自动解压，仅导入白名单后缀（jpg/jpeg/png/bmp/gif）图片，其余文件忽略。
- REQ-6.2-2 XML 配对：图片与同名 XML 配对导入；图片缺失 XML 时该图被跳过并列入错误列表，不影响其余图片导入。
- REQ-6.2-3 错误处理：损坏 ZIP、无有效图片分别给出明确报错，且不产生残留/孤儿文件。
- REQ-6.2-4 进度与汇总：导入过程有进度反馈，结束后展示导入数、跳过数、错误明细。
- REQ-6.2-5 时间范围拉取：用户指定起止时间，系统从内置库拉取 timestamp 落在区间内的记录进入目标数据集。
- REQ-6.2-6 质量过滤：拉取时按质量过滤，默认「只保留质量合格」图片，可切换为「全部」；选择只保留合格时，结果中仅含 quality 为「合格」的记录。
- REQ-6.2-7 拉取不破坏源库：拉取仅复制记录关联到目标数据集，不移动、不删除内置库数据。
- REQ-6.2-8 内置库填充：ZIP 导入的数据同时写入内置库记录，供后续按时间范围拉取。

**验收标准**：构造含图片、缺 XML 图片、非图片文件的 ZIP，导入后图片数与汇总正确，缺 XML 项列入错误列表；按时间范围 + 质量过滤拉取，结果记录集合与预期一致。

### 6.3 图片浏览检索

**需求描述**：标注页支持图片浏览：上一张/下一张切换、进度条跳转、当前位置显示（n/m）、文件名搜索；并展示该图的舌/面/脉/声音结构化标签。

**可验收条目**：

- REQ-6.3-1 翻页：通过上一张/下一张按钮切换图片，边界（首张/末张）处理正确。
- REQ-6.3-2 进度条：拖动进度条可跳转到任意位置，界面显示当前位置 n/m。
- REQ-6.3-3 搜索：按文件名模糊搜索，命中结果可定位到对应图片；无结果时给出空状态提示。
- REQ-6.3-4 结构化标签展示：图片旁展示其当前舌/面/脉/声音四类标签（读取自该图 XML）。

**验收标准**：3 张图片的数据集上，翻页、进度条跳转、搜索命中、无结果提示均正确；标签展示与 XML 内容一致。

### 6.4 标注操作

**需求描述**：通过标注面板为当前图片打标签；标签变更自动保存至 XML，无需手动保存；支持删除当前数据及其标注文件。

**可验收条目**：

- REQ-6.4-1 标注面板：舌/面/脉/声音四类并列展示，每类子标签单选。
- REQ-6.4-2 自动保存：选中标签后系统自动写入该图 XML，无需手动保存；翻页前标签变更不丢失。
- REQ-6.4-3 快捷键：方向键左/右切上一张/下一张；数字键 1、2、3、4 切换类别；Q 切换「质量合格」标记（再按一次清除）；S 为手动保存兜底。
- REQ-6.4-4 质量标记：标注页可勾选「质量合格」，写入 XML 的 quality 字段并镜像到数据库；「不合格」仅由导入的 XML 带入，标注页不直接设置。
- REQ-6.4-5 删除：可删除当前数据（记录行 + 对应 XML 文件），需二次确认；内置库中的源记录不受影响。
- REQ-6.4-6 写入完整性：快速连续修改标签时，最终 XML 完整且为最后一次选择（原子写，无半截文件、无竞态脏数据）。

**验收标准**：选中某标签后立即读取该图 XML 验证已更新；删除后记录与 XML 均消失且源库记录仍在；连续快速修改后 XML 完整。

### 6.5 标注导出

**需求描述**：将整个数据集导出为一个 ZIP 包，包含全部图片与对应标注 XML。

**可验收条目**：

- REQ-6.5-1 完整性：导出图片数等于数据集记录总数，每张图片有对应同名 XML（含 quality 字段）。
- REQ-6.5-2 未标注记录导出：labels 为空（0 个 label）的未标注记录同样导出，不跳过。
- REQ-6.5-3 往返保真：导出 ZIP 再经导入后，标签与 quality 与原数据逐字节一致。
- REQ-6.5-4 空数据集：空数据集导出返回空 ZIP 或明确提示（HTTP 200/204），不报错崩溃。

**验收标准**：导出后解压校验条目数与内容；再导入后比对 XML 逐字节一致。

### 6.6 数据集选择（训练用）

**需求描述**：训练时选择一个主训练集，并可叠加多个额外数据集进行混合训练。

**可验收条目**：

- REQ-6.6-1 主训练集：必须且只能选择一个主训练集。
- REQ-6.6-2 叠加数据集：可多选额外数据集，与主训练集混合构成训练数据。
- REQ-6.6-3 标签体系一致性校验：训练开始前校验主训练集与全部叠加数据集的标签体系一致，不一致时拒绝启动训练并给出明确报错。

**验收标准**：主集 + 叠加集组合可正常训练；taxonomy 不一致时训练启动被拒绝并报错。

### 6.7 模型架构

**需求描述**：支持 ResNet18、ResNet50 两种预置骨干网络，以及用户上传的自定义模型；模型输出 4 个分类头，分别对应舌/面/脉/声音。

**可验收条目**：

- REQ-6.7-1 预置骨干：可选择 ResNet18 或 ResNet50（使用预训练权重初始化）。
- REQ-6.7-2 四分类头：模型输出 4 个并行分类头，每头输出维度等于该类别子标签数，各头独立预测。
- REQ-6.7-3 自定义模型：可上传自定义模型文件并加载使用；文件不符合约定接口时给出明确错误。
- REQ-6.7-4 能力边界：ONNX 一键转换与模型结构自动读取仅对 ResNet18/50 保证；自定义模型按尽力支持处理，失败时显式报错而非崩溃。

**验收标准**：ResNet18/50 构建后前向输出 4 个 logit，维度与各类别子标签数一致；自定义模型符合接口时可用，不符合时明确报错。

### 6.8 GPU

**需求描述**：系统自动检测 GPU 数量，支持单卡/多卡/CPU 训练；GPU 可用时支持 FP16 混合精度。

**可验收条目**：

- REQ-6.8-1 自动检测：启动训练时自动检测可用 GPU 数量并在界面展示。
- REQ-6.8-2 设备选择：0 块 GPU 时使用 CPU 训练；1 块时单卡训练；多块时多卡并行训练。
- REQ-6.8-3 FP16：GPU 可用时支持开启 FP16 混合精度加速；无 GPU 或 FP16 不可用时以全精度（FP32）运行且训练正常完成。

**验收标准**：不同 GPU 数量下设备选择正确；无 GPU 环境自动降级 CPU 且训练完成；FP16 开关可配置。

### 6.9 参数可调

**需求描述**：训练超参数全部可由用户配置。

**可验收条目**：

- REQ-6.9-1 学习率（learning rate）可调。
- REQ-6.9-2 批量大小（batch size）可调。
- REQ-6.9-3 训练轮数（epochs）可调。
- REQ-6.9-4 优化器可选（SGD / Adam / AdamW）。
- REQ-6.9-5 Dropout 概率可调（作用于各分类头）。
- REQ-6.9-6 损失函数可选（CrossEntropy 默认 / FocalLoss 备选），作用于全部 4 个分类头并对各头损失求和。

**验收标准**：修改任一超参数后训练按新值生效（如 epochs 修改后训练轮数随之变化）。

### 6.10 数据增强

**需求描述**：训练前可多选数据增强方式，按勾选组合应用于训练数据。

**可验收条目**：

- REQ-6.10-1 支持 RandomFlip（水平翻转）、RandomRotation、ColorJitter、RandomCrop 四种增强。
- REQ-6.10-2 多选组合：用户勾选多项时，训练按所选组合应用增强；增强仅作用于训练数据，验证与推理不增强。

**验收标准**：勾选不同增强组合均可正常训练，验证/推理数据不受增强影响。

### 6.11 断点续训

**需求描述**：训练中断（异常退出、手动停止、断电等）后，可从已有训练存档恢复并继续训练。

**可验收条目**：

- REQ-6.11-1 存档选择：用户可选择本地已有训练存档（checkpoint）作为训练起点。
- REQ-6.11-2 状态恢复：恢复模型参数、优化器状态、已训练轮数、最佳指标追踪，继续训练不从零开始。
- REQ-6.11-3 存档校验：存档包含模型结构信息与各类别类别数，加载时自动校验；损坏或不匹配的存档给出明确错误。

**验收标准**：从指定存档恢复训练后，起始轮次等于存档记录值且可正常继续至结束；损坏存档报错明确。

### 6.12 训练监控

**需求描述**：训练过程中实时展示当前轮次、损失、训练准确率、验证准确率，并以动态曲线呈现。

**可验收条目**：

- REQ-6.12-1 实时指标：每个轮次（epoch）结束后更新并展示当前轮次、损失、训练准确率、验证准确率。
- REQ-6.12-2 动态曲线：损失曲线与准确率曲线随训练推进自动追加更新，无需用户手动刷新。
- REQ-6.12-3 后台训练：训练在后台执行，不阻塞页面其它操作；用户可手动停止训练。
- REQ-6.12-4 监控恢复：页面刷新后，曲线可依据已记录指标重建。

**验收标准**：训练进行中曲线数据点随轮次递增；停止训练生效；刷新页面后曲线可重建。

### 6.13 评估可视化

**需求描述**：训练结束后，对验证集结果进行可视化评估：混淆矩阵 + ROC 曲线。

**可验收条目**：

- REQ-6.13-1 混淆矩阵：每个类别（舌/面/脉/声音）各输出一张子标签 × 子标签混淆矩阵。
- REQ-6.13-2 ROC：每个类别输出一对一（one-vs-rest）ROC 曲线并标注 AUC 值。
- REQ-6.13-3 概率保留：评估基于模型输出概率（非硬标签），推理结果必须保留各类别概率。
- REQ-6.13-4 计算范围：混淆矩阵与 ROC 仅对验证集计算；无验证集时给出「暂无评估结果」提示而非报错。

**验收标准**：训练结束后评估页面渲染 4 张混淆矩阵与 4 组 ROC 曲线（含 AUC）；空评估结果时页面给出提示不白屏。

### 6.14 模型加载/保存

**需求描述**：可从本地模型目录选择权重加载；训练自动保存最佳模型与最新存档至用户指定目录。

**可验收条目**：

- REQ-6.14-1 权重加载：可从本地模型目录选择训练产物（checkpoint）加载使用。
- REQ-6.14-2 最佳模型保存：训练过程中自动保存最佳模型，判据为 4 个分类头宏平均验证准确率的算术均值最大；保存到用户指定的模型目录。
- REQ-6.14-3 存档保存：每轮保存最新存档（latest）与最佳存档（best）。

**验收标准**：训练完成后指定目录出现 best 与 latest 存档；best 对应宏平均验证准确率最大的轮次。

### 6.15 推理数据集选择

**需求描述**：推理前选择推理目标数据集与所用模型。

**可验收条目**：

- REQ-6.15-1 数据集选择：从数据集下拉列表选择推理数据集。
- REQ-6.15-2 模型选择：从本地模型目录选择模型权重；无可用模型时给出提示。

**验收标准**：选定数据集与模型后能进入批量预测流程；无模型时提示明确。

### 6.16 批量预测

**需求描述**：对选定数据集整批执行推理，输出每图每类预测结果。

**可验收条目**：

- REQ-6.16-1 批量推理：一次对数据集中全部图片执行推理。
- REQ-6.16-2 输出内容：每张图片每类输出预测子标签 + 概率（软输出，非仅硬标签）。
- REQ-6.16-3 模型结构自动识别：从所选模型自动重建网络结构并载入权重；无法识别结构的第三方权重给出明确错误。

**验收标准**：批量预测返回结果数等于数据集图片数，每条含 4 类预测子标签与概率；损坏/未知权重报错明确。

### 6.17 结果表格

**需求描述**：批量预测结果以表格展示。

**可验收条目**：

- REQ-6.17-1 表格列：文件名 + 舌/面/脉/声音各类别预测值（预测标签与概率）。
- REQ-6.17-2 行数一致：表格行数等于推理图片总数。

**验收标准**：预测完成后表格行数等于图片数，每行含文件名与 4 类预测值列。

### 6.18 预标注 XML 生成

**需求描述**：基于推理结果生成与标注界面完全兼容的预标注 XML 文件；源模型从本地模型目录选择，系统自动读取模型结构。

**可验收条目**：

- REQ-6.18-1 兼容性：预标注 XML 与人工标注 XML 采用同一 schema，可被标注界面直接读取与编辑。
- REQ-6.18-2 置信度：label/confidence 写入模型预测概率（0 到 1 区间）。
- REQ-6.18-3 源模型选择：从本地模型目录选择源模型，系统自动读取模型结构。
- REQ-6.18-4 不覆盖人工标注：预标注只生成到独立输出目录或仅针对未人工标注的图片，不覆盖已有标注。

**验收标准**：生成的预标注 XML 可被标注界面读取，category/name/confidence 与预测结果一致；已有人工标注的图片未被覆盖。

### 6.19 PyTorch→ONNX 一键转换

**需求描述**：将训练好的模型一键转换为 ONNX 格式。

**可验收条目**：

- REQ-6.19-1 一键转换：选择模型后一次操作即可完成导出，生成 .onnx 文件。
- REQ-6.19-2 范围保证：ResNet18/50 保证可转换；自定义模型转换失败时显式报「该模型不支持一键转换」，不崩溃。
- REQ-6.19-3 产物可用：生成的 .onnx 可被 ONNX Runtime 正常加载。

**验收标准**：ResNet18/50 训练产物转换成功且产物可加载；自定义模型不支持时提示明确。

### 6.20 精度对比

**需求描述**：转换后自动对比 PyTorch 与 ONNX 在同一输入下的输出差异。

**可验收条目**：

- REQ-6.20-1 逐头对比：对 4 个分类头分别计算 PyTorch 与 ONNX 输出差异。
- REQ-6.20-2 判定阈值：每头最大绝对误差 < 1e-3 判为通过（PASS），否则标记不通过。
- REQ-6.20-3 报告展示：对比结果（各头差异值与通过与否）以报告形式呈现给用户。

**验收标准**：转换后自动执行对比，报告含 4 个头的最大绝对误差与通过状态；正常转换产物 4 头均 PASS。

### 6.21 ONNX 模型一键下载

**需求描述**：转换后的 ONNX 模型可一键下载。

**可验收条目**：

- REQ-6.21-1 下载：点击下载按钮获取 .onnx 文件，下载文件完整且可被 ONNX Runtime 加载。

**验收标准**：下载的 .onnx 文件与原产物一致，可正常加载推理。

## 7. 非功能需求

### 7.1 性能

- NF-7.1-1 单张图片标注切换（翻到下一张并完成界面就绪）响应时间 < 200ms。
- NF-7.1-2 ZIP 导入过程提供进度反馈，导入结束后给出汇总统计。
- NF-7.1-3 训练在后台执行，训练期间标注、浏览、推理等操作不被阻塞。
- NF-7.1-4 训练监控指标在每个轮次结束后即更新，曲线更新无需手动刷新。

### 7.2 易用性

- NF-7.2-1 标注核心操作（翻图、切类别、选标签、质量标记、保存）均可通过键盘完成，无需依赖鼠标。
- NF-7.2-2 关键破坏性操作（删除数据、删除数据集）需二次确认，防止误操作。
- NF-7.2-3 界面提供状态提示：当前数据集、当前图片位置（n/m）、导入/训练进度。
- NF-7.2-4 错误信息使用可读的自然语言，说明错误原因与处理建议。

### 7.3 健壮性

- NF-7.3-1 损坏 ZIP 上传：明确报错，不产生残留/孤儿文件。
- NF-7.3-2 图片缺失同名 XML：跳过并列入错误清单，不影响其余数据导入。
- NF-7.3-3 非法标签（标签名不在标签体系内）：读取/导入时明确报错或跳过并记录，不写入脏数据。
- NF-7.3-4 训练中断（异常退出/断电）：已保存存档可用，可断点续训。
- NF-7.3-5 XML 快速连续写入：原子写保证最终文件完整，无半截文件。
- NF-7.3-6 无 GPU 环境：自动降级 CPU 训练，功能不缺失、不崩溃。

### 7.4 安全性

- NF-7.4-1 上传文件类型校验：仅接受白名单类型（数据导入仅 ZIP，自定义模型仅 Python 模型文件），其余类型拒绝。
- NF-7.4-2 上传文件大小校验：超过限制给出明确提示并拒绝。
- NF-7.4-3 自定义模型执行风险声明：上传的模型代码将在本机 Python 进程内加载执行，系统必须向用户明确声明该风险。
- NF-7.4-4 路径安全：导入、导出、模型读写均限定在系统管理的目录内，不接受任意路径写入。

### 7.5 可维护性

- NF-7.5-1 前后端分离，后端按功能模块（数据管理/标注/训练/推理/转换）分层组织。
- NF-7.5-2 标签体系、数据/模型/导出目录等配置集中于配置文件与环境变量，修改无需改代码。
- NF-7.5-3 标签与质量以 XML 为唯一真相源，数据库仅镜像必要字段，避免双源漂移。
- NF-7.5-4 核心模块（XML 读写、导入导出、训练、推理、ONNX 转换）具备自动化测试覆盖。

## 8. 约束与假设

- **C-1 标签子项为占位默认值**：舌/面/脉/声音每类的子标签当前为占位默认值，用户可在配置文件（labels.yaml）中修改为真实标签；每类第一项固定为「正常/无」。
- **C-2 质量过滤语义**：需求 6.2 中「过滤质量合格图片」按「只保留合格」实现，可通过选项切换为「全部」。
- **C-3 内置库填充方式**：内置四诊数据库由 ZIP 导入填充（导入即入库）；「按时间范围拉取」从库中重选记录进入数据集，拉取为复制关联，不物理移动数据。
- **C-4 质量标记简化**：不做独立的质量审核模块，仅在标注页提供「质量合格」勾选；「不合格」由导入 XML 带入。
- **C-5 删除语义**：删除数据/数据集为硬删除当前数据集内的记录与 XML；内置库源记录因复制关联天然不受影响，不做软删除标记。
- **C-6 分类语义**：模型为 4 个独立分类头（多任务多分类），每头对各自子标签做多分类；若实际需求为「一张图只归四类之一」或「每类可同时多选子标签」，需在实现前纠正本假设。
- **C-7 环境假设**：开发机可能无 GPU，GPU 相关功能（多卡、FP16）在无 GPU 环境以 CPU 降级路径验证，真实 GPU 路径在 GPU 服务器上验证。
- **C-8 单机单用户**：本系统为单机使用，无登录与权限，不假设并发多用户协作。
