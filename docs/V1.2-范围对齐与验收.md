## 一、四诊系统 21 项对照

“已有”指仓库中能定位到实现，表中右列是验收动作或尚缺内容。表内业务路径统一使用 `/api` 前缀。真实数据和 GPU 另行验证。

| V1.2 条款 | 后端与现状 | 验收动作与差距 |
| --- | --- | --- |
| .1 数据集管理 | `/api/datasets` 提供列表、创建、重命名、删除和四诊类型及统计，旧记录的类型可为空 | 验证同名 409、显式选择四诊类型、空集与有标注集的真实进度。计数包含已有模型建议，人工真值需另核 |
| .2 数据导入 | ZIP 导入和按时段拉取落批次记录，可查 UTC 时间、来源、文件/范围、结果与操作者。按图片 SHA-256 和记录时间去重 | 验证同名文件和重复请求不会覆盖或重复。当前内置源是其他本地数据集，真实业务源的字段映射待核对 |
| .3 图片浏览与检索 | `/datasets/{id}/images` 系列接口和标注页提供前后翻页、跳转、按文件名定位。标注详情显示文件大小和记录时间 | 验证中文、下划线、百分号和空结果。采集人脱敏字段无可靠来源，记录时间可能来自文件时间 |
| .4 标注操作 | `PUT /datasets/{id}/image/{filename}/labels` 将标签和质量写入 XML，过期修订返回 409。标注历史按图片生命周期隔离 | 用两账号编辑同一图验证冲突处理，并检查快捷键、自动保存、删除和重建 |
| .5 标注数据导出 | `GET /datasets/{id}/export` 输出图片和配对 XML 的 ZIP | 导入另一空数据集并逐条对照图片和 XML；采集时间与来源另行验收。V1.2 字段段落重复了导入记录，本轮按其导出功能说明验收 |
| .6 数据集选择 | `POST /training/start` 接收主集和多个附加集；现有训练准备步骤过滤不适合训练的标注 | 验证主集、附加集及无有效样本时的提示。按人/病例划分和冻结样本清单需真实分组 ID |
| .7 模型架构 | ResNet18/50 与管理员自定义模型上传，自定义源码按内容摘要保留版本 | 用三种模型各走一次实际训练入口。自定义 Python 按可信代码管理 |
| .8 GPU 支持 | CUDA 检测、CPU 路径、DataParallel、FP16 已有代码 | 2026-11-09 已在目标机（2×RTX 3090）完成实机验证：单卡 AMP 冒烟与双卡 DataParallel AMP 冒烟均通过，GPU 温度/利用率/显存遥测按实机核对；CPU 回退由本地全量验收覆盖 |
| .9 参数可调 | 训练请求和服务校验学习率、batch、epoch、优化器、Dropout、损失 | 验证错误参数不启动任务，合法参数进入 checkpoint 配置 |
| .10 数据增强 | 服务支持翻转、旋转、颜色抖动、裁剪及组合 | 验证训练集启用组合策略，验证集使用稳定预处理 |
| .11 断点续训 | `POST /training/resume` 从 checkpoint 恢复 | 验证恢复模型/优化器/轮次，错误与越界存档拒绝。当前跨重启恢复依靠文件 |
| .12 训练监控 | `/training/status` 轮询及 `/api/training/ws/training` 推送轮次、损失和准确率，任务与曲线保存在进程内 | 首帧、后续增量与刷新已核验；GPU 遥测已在目标机核对。空闲断线清理、目标机 ETA 与持久化日志仍待补（单 worker 内存态属既定约束） |
| .13 评估可视化 | `GET /training/eval/{job_id}` 以最佳存档评估，输出混淆矩阵、ROC 和分类指标 | 验证无真值的头不会得到虚构曲线，报告记录测试划分和有效样本数 |
| .14 模型加载 | 模型目录枚举和 checkpoint 加载，训练保存 latest 和可用的 best | 验证错误模型、类别顺序不匹配和无验证集场景。部署仅接收明确选定的模型版本 |
| .15 推理数据集 | `POST /inference/predict` 以模型和数据集 ID 运行 | 验证数据集不存在、空集和合法数据集的响应。置信度配置按 .18 的实际接口核对 |
| .16 批量处理 | `POST /inference/jobs` 返回 202 与状态地址，按图片批次更新完成数。一个 worker 同时处理一个批量推理 | 验证超过单批容量时的进度与全量结果。状态和最近结果保存在当前进程 |
| .17 结果展示 | 批量推理返回文件名和各分类头结果，前端提供结果表 | 按同一数据集核对每行与来源图片、标签及置信度 |
| .18 预标注 XML | `POST /inference/preannotation` 复用 XML 格式，按置信度过滤，在写入前重新检查已有标签和人工编辑。仅改质量时保留模型标签来源和置信度 | 核对并发、低置信度、人工清空及仅改质量的场景 |
| .19 转换目标格式 | `POST /onnx/convert` 从 PyTorch 产出 ONNX，经结构和输出校验后发布，产物关联源 checkpoint 摘要 | 校验输入形状、opset 和四个输出头，跨模型转换不混用产物 |
| .20 精度对比 | `POST /onnx/compare` 对照 PyTorch 和 ONNX Runtime 输出，可选数据集按文件名取前 8 张图片进行比较 | 用授权测试图片核对数值差与 Top-1 一致性。合成输入用于转换冒烟，抽样比对用于核对运行时输出 |
| .21 模型下载 | `GET /onnx/{onnx_name}/download` 经登录下载，转换结果提供文件名、大小、时间 | 核对下载字节与输出一致，使用 ONNX Runtime 验证加载。接收端设备的加载和交接流程待部署验证 |

.2 的“过滤已标记为质量合格”存在两种读法。结合技术解决方案的文件交接描述和当前服务筛选，默认仅拉取明确标为「合格」的图片，显式选择「全部」时保持原行为。验收使用一份同时包含合格、不合格、未标记的样本。
