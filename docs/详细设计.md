本文档给出系统后端（FastAPI）的类级与函数级设计：每个模块的类/函数签名、全部 REST 端点与 WebSocket 端点的方法/路径/请求/响应/错误码、数据库表字段定义、标注 XML 字段定义、关键算法流程。本文档是编码与维护的对照基准，内容与 `backend/app` 代码一致；代码与文档冲突时以代码为准并同步修订本文档。

覆盖需求 6.1 至 6.21 全部 21 条功能需求对应的后端实现：数据管理、导入导出、图片浏览与标注、训练、监控、评估、推理、预标注、ONNX 转换与对比。范围边界同需求规格 2.3 节：不做目标检测、不做登录权限、不做多机分布式。

### 2.3 通用约定

| 约定 | 说明 | 落地模块 |
| --- | --- | --- |
| Session 自管 | 每个 service 函数用 `SessionLocal()` 上下文自管会话，不接收 db 参数 | 各 service |
| 目标不存在 | 一律抛 `ValueError`，由 router 统一转 404 | 各 service/router |
| 重名冲突 | 让 `IntegrityError` 上抛，由 router 转 409 | dataset_service |

| 未处理异常 | 全局处理器返回 500 `{"detail": "Internal server error: ..."}` | main.py |
| 时间戳 | DB 落盘统一 naive UTC（`_utcnow`） | orm.py / dataset_service |
| 原子写 | XML 用「临时文件 + os.replace」 | xml_io |

## 5. 数据模型与 Schema

### 5.1 ORM 模型（app/models/orm.py）

`def _utcnow() -> datetime`：返回 naive UTC 当前时间（SQLite 落盘干净、可跨行比较）。

#### 表 datasets

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | INTEGER | PK, autoincrement | 数据集主键 |
| name | VARCHAR(255) | UNIQUE, NOT NULL | 数据集名（重名 → IntegrityError → 409） |
| created_at | DATETIME | NOT NULL, default `_utcnow` | 创建时间（naive UTC） |
| updated_at | DATETIME | NOT NULL, default `_utcnow`, onupdate `_utcnow` | 更新时间 |

ORM 关系：`records: Mapped[list["Record"]]`，`cascade="all, delete-orphan"`。

#### 表 records

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | INTEGER | PK, autoincrement | 记录主键 |
| dataset_id | INTEGER | FK datasets.id ON DELETE CASCADE, NOT NULL, INDEX | 所属数据集 |
| filename | VARCHAR(255) | NOT NULL | 图片文件名（basename） |
| image_path | VARCHAR(1024) | NOT NULL | 图片绝对路径（`data/datasets/<dataset_id>/<filename>`） |
| timestamp | DATETIME | NULL | 采集时间/文件时间；未知允许 NULL |
| quality | VARCHAR(32) | NULL | 质量镜像（「合格」/「不合格」/''）；标签本身不入库 |
| created_at | DATETIME | NOT NULL, default `_utcnow` | 创建时间 |

设计边界（锁定决策 2/7/11）：标签不入库，唯一真相源是同名 XML，DB 仅镜像 quality 供 6.2 质量过滤快速查询；删除语义 = 硬删除（无 `deleted_at`）。

## 6. 标签体系（app/labels_config.py + backend/config/labels.yaml）

`labels.yaml` 是全系统标签唯一真相源，结构：

```yaml
categories:
  - name: 舌
    labels: [正常/无, 舌苔薄白, 舌苔黄, 舌苔黄腻, 舌质淡红, 舌质红]   # 占位默认值，可编辑
  - name: 面
    labels: [正常/无, 面色红润, 面色苍白, 面色萎黄]
  - name: 脉
    labels: [正常/无, 浮, 沉, 迟, 数]
  - name: 声音
    labels: [正常/无, 清晰, 低微, 嘶哑]
```

规则（锁定决策 1）：恰好 4 个 category，顺序即分类头顺序；每类第一个标签固定为「正常/无」默认类；同 category 内子标签不重复。

## 7. 标注 XML 格式（app/services/xml_io.py）

全系统标注 XML 的唯一真相源。人工标注写回（T10）与预标注生成（T17）共用本模块，保证结构一致。

### 7.1 XML 字段定义（锁定决策 2）

```xml
<annotation>
  <folder>dataset_name</folder>
  <filename>image.jpg</filename>
  <path>relative/path/image.jpg</path>
  <size><width>640</width><height>480</height><depth>3</depth></size>
  <quality>合格</quality>
  <labels>
    <label><category>舌</category><name>舌苔黄</name><confidence>1.0</confidence></label>
  </labels>
</annotation>
```

| 元素 | 取值 | 规则 |
| --- | --- | --- |
| annotation | 根元素 | 根元素非 `<annotation>` → `ValueError`（非法四诊标注 XML） |
| folder | 字符串 | 数据集名；空串序列化为自闭合标签 |
| filename | 字符串 | 图片文件名 |
| path | 字符串 | 相对路径（如 `<dataset_id>/<filename>`） |
| size | 可选 | 子元素 width/height/depth（int）；size 缺失/空 → 序列化时省略；子字段缺失解析为 None |
| quality | `合格` / `不合格` / '' | 空串序列化为自闭合标签 |
| labels | 0 至 4 个 label | 每 category 至多一个 label |
| label/category | 字符串 | 必须存在于 labels.yaml |
| label/name | 字符串 | category 下的子标签 |
| label/confidence | float | 人工标注 = 1.0；预标注 = 模型概率 [0,1]；解析缺失默认 1.0 |

### 7.2 接口

```python
def read_xml(path: Any) -> Dict[str, Any]:
    """解析 XML → dict：folder/filename/path/size/quality/labels。
    容忍缺失 <size>/<labels>/<quality>（各自按缺省处理）。"""

def write_xml(path: Any, data: Dict[str, Any]) -> None:
    """原子写：同目录 mkstemp 临时文件 + write/flush/fsync + os.replace 替换；
    失败时清理临时文件。序列化 canonical：write_xml(p, read_xml(p)) 产物逐字节一致。"""
```

序列化细节：字段顺序固定 `folder → filename → path → size(width,height,depth) → quality → labels`；confidence 用 `repr(float(value))` 最短可往返十进制表示；空字符串文本 → None（自闭合标签），保证唯一规范形式。

### 9.2 import_service.py（T7）

```python
IMAGE_EXTENSIONS = {".jpg", ".jpeg", ".png", ".bmp", ".gif"}   # 白名单，大小写不敏感
XML_EXTENSION = ".xml"

def import_zip(dataset_id: int, zip_bytes: bytes) -> dict[str, Any]:
    """解压 ZIP，白名单图片与同名 XML 配对后导入数据集。
    返回 {"imported": N, "skipped": [filenames], "errors": [messages]}。

    流程：
    1. 数据集不存在 → ValueError（router 转 404）。
    2. 解压到 UPLOAD_DIR 下临时目录（finally 整体删除，无孤儿文件）；
       BadZipFile 由此上抛（router 转 400），此时未产生任何落盘。
    3. 每个条目：跳过目录；仅取 basename（PurePosixPath(...).name，杜绝 Zip Slip
       穿越）；重复文件名 → errors；非白名单图片且非 .xml → 完全忽略不提取；
       解压后按 ZIP 条目原始 mtime os.utime 还原文件时间。
    4. 对每个图片：查同名 XML（stem 相同，大小写不敏感）：
       无同名 XML → 计入 skipped，不落盘不建记录（REQ-6.2-2）；
       XML 解析失败 → 计入 errors，不落盘不建记录。
    5. 成功者 shutil.copy2 落盘到 data/datasets/<dataset_id>/，建 Record：
       timestamp = XML 中 "timestamp" 键优先（前向兼容），否则文件 mtime；
       quality = XML quality（缺省 ''）。
    6. 单文件级失败只记入 errors，不影响其余图片。"""
```

### 10.3 WebSocket 帧协议（/api/training/ws/training）

| 帧 type | 触发时机 | 载荷 |
| --- | --- | --- |
| snapshot | 连接建立 | `{"type": "snapshot", "jobs": [公开视图含 metrics]}` |
| metrics | 每 epoch 指标追加 | `{"type": "metrics", "job_id", "metrics": [新增轮次...]}` |
| status | 状态变化 | `{"type": "status", "job_id", "status", "error", "finished_at"}` |

推送实现：训练线程追加指标/状态后只 `Event.set()`（非阻塞）；每个 WS 连接在自身事件循环经 `asyncio.to_thread(manager.metrics_event.wait, 0.5)` 唤醒（0.5s 既是唤醒等待也是兜底轮询节拍），按各自游标 `cursor[ job_id ]` 对 metrics 缓冲做 diff 增量发送；连接断开（WebSocketDisconnect）即退出。

## 11. 关键算法说明

### 11.1 四头前向（4-head forward）

1. 输入 `x: (B, 3, 224, 224)` 经共享 ResNet 主干（fc 已替换为 `nn.Identity()`）得特征 `feats: (B, in_features)`，in_features = 512（resnet18）/ 2048（resnet50）。
2. 4 个并行分类头 `heads = ModuleDict{舌, 面, 脉, 声音}`，每头为 `Sequential(Dropout(dropout), Linear(in_features, n_cat))`，n_cat = 该 category 子标签数（顺序与 labels.yaml 一致）。
3. `forward` 返回 `dict[str, Tensor]`：`{类别名: logits (B, n_cat)}`，键顺序与 `category_names` 一致。
4. 训练时逐头计算损失（CE 或 FocalLoss）后**求和**（REQ-6.9-6）；推理/评估时逐头独立 softmax。

### 11.2 数据增强管线

- 训练集：`_build_train_transform` 按配置勾选顺序组合 `_AUG_OPS` 中的操作（RandomHorizontalFlip p=0.5、RandomRotation 15°、ColorJitter 亮度/对比/饱和 0.3 色相 0.1、RandomCrop 196 并 pad_if_needed），末尾固定追加 `Resize(224,224) + ToTensor`。
- 验证集与推理：不增强，仅 `Resize(224,224) + ToTensor`（REQ-6.10-2，各头共享同一主干要求固定输入尺寸）。
- 增强配置输入经别名表归一化（如 `flip`/`hflip` → `randomhorizontalflip`），未知项 → ValueError（400）。

### 11.3 训练主循环与指标（TrainManager._train）

1. 固定 `torch.manual_seed(cfg["seed"])`；`resolve_device()` 选设备；`use_amp = n_gpus > 0 and cfg["fp16"]`。
2. 构建模型：`factory.build_model(architecture, num_classes, dropout)`；续训时 architecture 以存档为准并 `load_state_dict(payload["model_state"])`；>1 卡包 `nn.DataParallel`。
3. 恢复优化器/调度器状态（配置 lr 优先于存档恢复值）；构建 `GradScaler("cuda", enabled=use_amp)`。
4. `_split_train_val` 固定 seed 划分（续训与首训划分一致，best 判据可比）；构建 train/val DataLoader（num_workers=0）。
5. 每 epoch：`_train_epoch`（model.train，amp autocast 下前向，四头损失求和，scaler 反向）→ 停则 break → `_eval_epoch`（no_grad 验证；无验证集则以训练指标兜底 val，不报错）→ `scheduler.step()` → 追加 metrics 并 `_metrics_event.set()` → 每轮保存 latest → best_metric（= 4 头 macro val_acc 均值）提升时覆盖保存 best。
6. 停止：下一 batch/epoch 边界退出，落一份 latest 存档供断点续训，状态置 stopped；正常结束：对验证集计算混淆矩阵 + one-vs-rest ROC（`_collect_val_probs` → `_compute_eval_from_probs`），与 `status="completed"` 同锁原子更新（无验证集 → 空 dict 不报错，REQ-6.13-4）。
7. 任何后台异常 → `status="failed"` + error 文案。

### 11.4 Checkpoint 与断点续训

- 存档为 dict（契约键见 9.8 节），`torch.save` 落于 `MODEL_DIR/<job_id>_latest.pth` / `<job_id>_best.pth`。
- 续训路径：`POST /api/training/resume` → `_load_resume_payload` 校验（文件存在、dict 结构、architecture 受支持、num_classes/category_names 与当前 labels.yaml 逐头一致、可选 backbone 一致性）→ 与存档内 config 合并（显式传入的覆盖键优先，`exclude_unset`）→ `normalize_config` → 新 job 恢复 `model_state/optimizer_state/scheduler_state/epoch/best_metric`，从 `epoch+1` 继续训练 `epochs` 轮。
- 推理路径：`load_model_from_dir` 读同一契约（仅依赖 `architecture/num_classes/category_names/dropout/model_state` 重建并载权），第三方 .pth 因缺 `architecture/num_classes` → 明确 ValueError「无法识别模型结构」（REQ-6.16-3，锁定决策 8）。

### 11.5 评估计算

训练完成后对验证集前向一遍保留 softmax 概率（REQ-6.13-3）。逐类别（舌/面/脉/声音）：`confusion_matrix(targets, argmax(probs), labels=range(n_cls))` 得子标签混淆矩阵；`label_binarize` 二值化后与概率按列展平，`roc_curve` 得该类别 one-vs-rest micro 平均 ROC 曲线与 AUC。某类别无验证样本时该类别缺席；缓存缺失且 latest 存档可用时从存档重建模型重算（`_eval_from_checkpoint`）。

### 11.6 批量推理

`predict_dataset`：先 `_validate_model_taxonomy`（模型 4 头类别数与 labels.yaml 逐头一致，不一致硬失败），按 filename 升序取全部记录，batch size 16 分批：每张图片 `Image.open(...).convert("RGB")` → `Resize(224,224)+ToTensor` → `torch.stack` → `model(batch)` 得 4 头 logits dict → 逐头 softmax → 每图取每头 argmax 子标签 + 概率（round 6 位）。图片缺失/损坏 → 整批 ValueError（不静默跳过）。

### 11.7 ONNX 转换与精度对比

- 转换：`_validate_multihead_model` 校验四头结构（category_names 属性长度 4 + forward 返回 dict 且键集合一致），否则报「该模型不支持一键转换」（REQ-6.19-2）；`_TupleOutputWrapper` 把 dict 输出改为按 category_names 顺序的 4 元组；`torch.onnx.export(dynamo=False, opset_version=13, input_names=["input"], output_names=[head_0..head_3])` 导出 FP32 模型到 `EXPORT_DIR/<stem>.onnx`。
- 对比：同一 dummy 输入 `(1,3,224,224)` 分别过 PyTorch（eval+no_grad）与 `onnxruntime.InferenceSession`（CPUExecutionProvider，输入 feed dummy_input.numpy()）；每头 `max_abs_diff = max|pt_logits - ort_logits|`，`< 1e-3` 判 pass；`overall_pass = 全部头 pass`（REQ-6.20-1/2/3，锁定决策 5）。ONNX 输出头数不为 4 → ValueError。

### 11.8 XML 原子写

`write_xml`：目标同目录 `tempfile.mkstemp(prefix=".<name>.", suffix=".tmp")` → 写序列化字节 → `flush + os.fsync` → `os.replace(tmp, target)` 原子替换；异常时清理临时文件。快速连续修改标签时最终 XML 完整且为最后一次选择（REQ-6.4-6）。

### 11.9 ZIP 导入管线

见 9.2 节 `import_zip`：解压至 UPLOAD_DIR 临时目录（finally 清理）→ basename 提取（防 Zip Slip）→ 白名单/重复名过滤 → 图片与同名 XML 配对（stem 大小写不敏感）→ XML 解析 → copy2 落盘 + 建 Record（timestamp = XML 键优先、mtime 兜底）→ 汇总 `{imported, skipped, errors}`。

## 14. 设计约束与已知边界

1. **安全**：`load_custom_model` 直接执行用户 .py（无沙箱），仅应加载管理员放入模型目录的可信脚本；`import_zip` 仅取 basename 防 Zip Slip；所有文件名定位经 DB 精确匹配防路径穿越；model_path/onnx_name 限定在系统目录内（NF-7.4）。
2. **能力边界**（锁定决策 8）：模型结构自动读取与 ONNX 一键转换仅保证 ResNet18/50 系统产物；第三方/自定义模型显式报错，不猜测结构、不静默降级。
3. **标签唯一真相源**：labels.yaml；DB 不存标签，仅镜像 quality（锁定决策 2/11）。
4. **删除语义**：数据集删除不碰磁盘图片；单图硬删除记录行+图片+XML，内置库同图副本不受影响（锁定决策 7）。
5. **一致性硬失败**：训练启动、续训、推理前均校验模型/数据与当前 labels.yaml 的逐头类别数与 category 名一致，不一致 → 显式报错（锁定决策 6）。
6. **线程安全**：TrainManager 全部状态更新在 `threading.Lock` 内；训练线程只 `Event.set()` 从不阻塞发送；WS 端按游标做 metrics diff 增量推送。
