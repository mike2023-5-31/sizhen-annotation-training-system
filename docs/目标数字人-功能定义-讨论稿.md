## 一、文档定位与阅读说明

本文只回答两个问题：

1. **长什么样**——形态与神态，按由浅入深三个阶段给出（§三）。
2. **能干什么**——按三类服务对象与一个训练闭环给出（§四），并落到辨证思维（§五）与自进化机制（§4.4）。

阅读约定（全文统一）：

- 每条能力按四段式书写：**问题 — 方法 — 依赖资料与授权 — 如何验证**；
- 每条能力标注三态之一：**「可工程交付」**（成熟组件与工程流程即可实现）、**「需实验验证」**（效果或可行性未知，需对照实验结论）、**「待确认」**（依赖业务、专家或监管决定）；
- 涉及“内心推断 / 辨证依据”的输出，一律区分三种来源身份：**本人原始口述 / 导师审定整理 / 模型教学解释**（§5.4）；
- 数字人不替代医师；面向患者与学生的生成内容带来源与免责边界（§七）。

本文给出的时长、数量均为**试制建议值**，可被试制结果与专家意见调整；凡未冻结处一律标注「待确认」。

## 二、术语与边界

### 2.1 术语

| 术语 | 定义 |
| --- | --- |
| 目标数字人 | 为一位名老中医构建的“形象—声音—辨证思维—互动”一致的数字人；本文定义其目标功能 |
| 三类服务对象 | 医生本人（训练者）、患者与健康人群、医学院学生 |
| 训练闭环 | 医生以真实资料持续“供给—纠正—审订”，驱动数字人版本迭代的机制（§4.1） |
| 形态阶段 L1/L2/L3 | 静态形象+口型 → 受控三维+表情神态 → 全身/展陈等扩展（§三） |
| 四种处方类型 | 中药处方、针灸、推拿、情绪/心理（情志）（§5.3） |
| 三来源身份 | 本人原始口述 / 导师审定整理 / 模型教学解释（§5.4） |
| 交互状态机 | 驱动神态表达的可见交互状态：倾听、检索、讲解、资料不足、降级（§3.0） |
| 教学证据单元 | 由原始片段、问题情境、支持与反对信息、适用条件、讲述时间与审定状态组成的最小教学材料（承 v1.3 §六.1） |

### 2.2 一句话定义

为一位名老中医构建可被长期训练、可被问询、可被学习的数字人：**医生本人用真实资料训练它；患者与健康人群与它互动问诊（辅助定位）；医学院学生用它学习诊断依据；它在三类互动中经审核地持续改进**——最后一层是本次口径中标出的创新空间（§4.4）。

### 2.3 边界总声明（先立于此，全文适用）

- 本文定义“目标能力”；实现按 §八 分期推进，每期只对「可工程交付」部分作出交付承诺，其余为探索或待确认。
- **形象逼真、问答流畅只代表部分体验质量**：不代表名医经验被保留，更不等于诊疗效果（§8.2）。
- 医疗与合规底线（详见 §七）：AI 辅助定位；不替代医师；不向患者自动处方；AI 生成内容按适用要求标识。

## 三、长什么样：形态与神态（三层递进）

### 3.0 总原则

- 目标气质：**“像一位可信、稳重、术语准确、经得起长时相处的老中医”**。要求高于直播带货数字人：不是炫技式逼真，而是可打断、状态明确、表达连贯、术语发音正确、长时间观看自然。
- 各形态共享同一份已发布资料版本；形态升级不得出现不同的知识归属。
- **神态由可观察的交互状态驱动**（倾听 / 检索 / 讲解 / 资料不足 / 降级）；不用“皱眉”暗示真实思考，不用笃定语气替代证据。
- “像个活生生的人”的操作定义：口型对齐、状态连贯、可中断可恢复、久看自然——四项均可测（见各阶段指标）。
- 状态标注：「可工程交付」（体验标准由试制收紧）。

### 3.1 L1 短期：静态形象 + 口型（“图片+嘴巴会动”）

**问题**：名医影像稀缺；短期内最现实的是用授权照片/短片，先做出“会讲解的形象”。

**方法（含驱动方式）**：授权正面照/半身照 → 音频驱动唇形（图像说话头路线）；或授权录制片段循环播报。语音经“识别—术语校正—文本确认—合成—口型驱动”处理链。

**依赖资料与授权（最小输入数据，试制建议值）**：1 张高清正面照（可做口型演示）；3–5 张多角度照片（提升稳定）；授权音视频素材合计 ≥10 分钟（覆盖常用术语与表达）。肖像与声音分别登记授权。

**如何验证（可测指标，各留记录）**：术语发音抽查正确率；口型-音素同步抽查误差；可打断；首段语音延迟 P95；长时观看自然度抽样评价。

**进入条件**：取得授权素材与审订人。

**完成标准**：独立完成一段 3 分钟教学讲解演示；上述五项指标均有记录。

**状态标注**：「可工程交付」（素材数量与指标阈值「待确认」）。L1 不做自由表情与身体动作；对外不得描述为“成熟数字分身”。

### 3.2 L2 中期：受控三维 + 表情神态 + 上半身动作

**问题**：需要视角变化、表情与少量手势时，静态形象不够用。

**方法（含驱动方式）**：三维表面扫描或多视角照片（约 20–30 张，试制建议值）→ 可驱动头部模型（口型、表情、头部姿态）；“少量照片生成数据源”的稀疏视图重建路线（本项目在此方向已有前期积累，属研究资产）；上半身骨架/主动骨架 + 经审核动作库（点头、手势、书写示意）。

**依赖资料与授权（最小输入数据）**：扫描/多视角影像及二次加工与跨终端使用授权；动作库来源与授权。

**如何验证（可测指标）**：身份相似度（盲评 + 客观身份保持）；表情/口型/音素同步抽查；动作自然度；目标设备端到端延迟；术语口型词典修正机制在案。

**进入条件**：L1 完成；素材满足试制要求；目标设备选定。

**完成标准**：“半身讲解”场景端到端可用（讲解—追问—回答不穿帮），并列出失败降级路径。

**状态标注**：「需实验验证」（重建与驱动的保真度、成本由试制确定；其中成熟组件部分属「可工程交付」）。**明确**：把脉、书写等动作是动作演示，不代表系统获得脉象或掌握操作技能。

### 3.3 L3 后续：全身动作 / 展陈 / 多终端（扩展选项，不默认必做）

**问题**：展陈、远程示教、AR/VR 等场景是否需要更强的形态表现。

**方法**：全身动作演示、示教大屏、AR/VR、移动端轻量形象——按场景逐项立项。

**驱动方式**：按立项场景逐项定义（预渲染播放 / 动作库驱动 / 全身动作捕捉），立项时冻结。

**依赖资料与授权（最小输入数据）**：按立项场景逐项定义素材清单（场地、设备、素材授权与预算确认）。

**如何验证（可测指标）**：场景级验收——可用性、稳定性、端到端延迟，不为“更炫”单独投入。

**进入条件**：L2 的教学价值获得验证；场景与预算明确。

**完成标准**：按立项场景逐项定义。

**状态标注**：「待确认」。

### 3.4 形态层防误解口径

- “活生生”不等于拟人化噱头；表情与语气服务于交流，不承担“背书”内容真实性的职责。
- 形态与内容责任分离：形象负责表达；来源与审订负责可信（§5.4、§七）。

## 四、能干什么：三类服务对象 + 一个训练闭环

### 4.0 总览

| 服务对象 | 核心能力 | 章节 | 主要需求映射 |
| --- | --- | --- | --- |
| 医生本人 | 训练数字人（每日/每周训练协议、数据规范、审订与版本） | §4.1 | REQ-8.5.x |
| 患者与健康人群 | 互动问诊（分期：科普 → 辅助问诊 → 辨证参考建议） | §4.2 | REQ-8.6.x、REQ-8.7.x |
| 医学院学生 | 教学互动（诊断依据与原理讲解、模拟问诊） | §4.3 | REQ-8.4.x、REQ-8.2.x |
| （闭环）互动中自我进化 | 反馈 → 筛选 → 审订 → 离线评估 → 版本发布（创新空间） | §4.4 | REQ-8.7.5 |

### 4.1 面向医生本人：训练数字人

**问题**：如何用本人真实资料持续训练，使数字人“越来越像本人”（限于约定病种与教学情境内的可观察特点），且训练可持续、可审核、可回滚。

**方法（训练协议：回答“我每天给它做哪些训练”）**——下表为建议试运行方案，时长与频次待与本人商定（「待确认」）：

| 周期 | 动作 | 约时长 |
| --- | --- | --- |
| 每日 | 诊后回看口述 1–2 例：当时最关注的证据、考虑过的其他解释、为何这样处理、什么情况会改变判断（小程序采集） | 10–20 分钟 |
| 每日 | 对数字人当天回答挑 1 条纠错：错在哪、正确说法、依据（纠错入口，留痕） | 5 分钟 |
| 每周 | 提交 3–5 个结构化医案；审订 1 组数字人示例回答（通过/修订）；补录 1 段 5–10 分钟讲解或语音素材 | 1–2 小时 |
| 每月 | 风格保真盲评（10–20 例病情相近病例，隐藏姓名与口头禅）；更新常用表达与术语表；参加一次版本发布评审 | 2–3 小时 |

**依赖资料与授权（数据规范）**：

- 结构化医案最小字段集（主诉 / 现病史 / 四诊 / 辨证 / 治法 / 方药 / 医嘱 / 复诊），schema 经专家确认后冻结（DEC-12）；
- 诊后口述与现场记录**分开保存**——口述是“事后解释”，不倒填成现场心理过程；
- 模态规范：音频（采样率/降噪/转写对齐）、视频（分辨率/帧率/时长/设备）、图片（四诊材料采集条件）；引擎与版本随资产登记（DEC-13）；
- 授权与脱敏：患者信息最小化与脱敏；医案、形象、声音分别登记授权范围与期限（§七）。

**手段（工具）**：移动端口述与上传；结构化医案编辑器；纠错与审订面板（修改留痕、版本比较）；风格画像报告（辨证/方药偏好分布，每条可回到来源医案）。

**如何验证**：风格保真评估（相近病例 + 隐藏姓名与口头禅的盲评 + 审定依据）；回答错误率与有效覆盖率；专家修订所需时间的变化；训练数据体检报告（纳入/排除数量与原因，承 REQ-8.5.5）。

**机制说明**：训练影响一律**离线**生效——反馈进入待处理队列 → 评估 → 新版本发布（可回滚），不直接在线自动更新（承 v1.3 §三 流程）。

**状态标注**：「可工程交付」（采集、审订、版本机制）；“越训越像”的量化「需实验验证」。

### 4.2 面向患者与健康人群：互动问诊（分期 + 辅助定位）

**问题**：患者与健康人群需要“问得到、听得懂、知道下一步”，同时必须守住医疗合规底线。

**合规口径（先于功能）**：按《互联网诊疗监管细则（试行）》的“AI 辅助”范围设计——不替代医师、不自动开方；面向个人的内容一律标注“参考建议”；处方须执业医师确认；公众入口只开放经审定的科普内容（承 v1.3 §十）。

**方法（能力清单，按分期）**：

| 期 | 能力 | 说明 |
| --- | --- | --- |
| P1 | 健康科普问答；院内导诊式信息整理（为医师准备问诊摘要） | 对审定的科普内容作答；不针对个人辨证 |
| P2 | 辅助问诊：多轮采集与“十问”框架引导；信息四态（已确认/已否认/未问/无法判断）管理；就诊摘要整理；资料缺口提示 | 院内/合作机构场景，医师在环；须先通过合规评估 |
| P3 | 面向个人的“辨证参考建议”（含四类处方方向的参考） | 需院内或监管允许的形态与医师在环，且完成对照验证后试点 |

**依赖资料与授权**：医案与科普内容授权与审订；患者交互数据的知情同意与脱敏；平台合规形态（院内 / 合作机构 / 公众）确认。

**如何验证**：问诊完整度（关键信息覆盖）；关键遗漏与重复追问率；矛盾信息处理；危险信息识别与转线下建议触发率；越界请求拒绝的评估脚本覆盖。任一指标不达标，不扩大场景。

**状态标注**：P1「可工程交付」；P2「需实验验证 + 待确认（合规）」；P3「待确认」。

### 4.3 面向医学院学生：教学互动

**问题**：学生对数字人的需求是“听懂凭什么这样辨证、这样用药”，而不只是拿到答案。

**方法（能力清单）**：

- **医案讲解模式**：完整原案 + 依据面板（支持依据 / 反对依据 / 尚缺信息 / 原案处理 / 适用条件），每条可回到材料；
- **模拟问诊模式**：按练习阶段渐进披露资料，答案、后续结果与点评在提交前隐藏；学员自主追问；
- **角色纪律**：数字人扮演讲解导师；若增设虚拟患者，必须是独立角色，防止“提供标准答案的角色”与“扮演患者的角色”混同（承 v1.3 §四.4）；
- **讲解范围**：诊断依据链、术语与原理、相似病例对照；材料未记录处如实显示“原资料未记录”，不编造。

**依赖资料与授权**：经审订的教学证据单元；导师点评机制；学员学习记录（按学员隔离）。

**如何验证**：前测/后测 + 新病例迁移 + 延迟测验；依据理解的准确性；错误建议识别；导师评分与评分分歧记录；满意度与“因形象产生的盲从”分开报告。

**状态标注**：「可工程交付」（讲解与面板）；学习成效「需实验验证」。

### 4.4 互动中自我进化（创新空间）

**问题**：导师口径指出——数字人要在与医生 / 患者 / 学生的互动中**持续学习进步**，并把“激励 / 进化机制”建起来；导师称此层“上升到新阶段”，是当前定义中的创新空间，也是最需要实证的部分。

**方法（闭环机制设计）**：

1. **采集**：医生纠正与审订意见、学员错误与高频提问、患者高频问题（脱敏后）进入反馈池；
2. **筛选**：按类别（事实错误 / 风格偏差 / 追问策略 / 表达问题）挑选，错误样本优先；
3. **审订**：由导师或专家确认哪些进入候选知识、策略或表达更新；
4. **离线评估**：回归评估（旧能力不退化）+ 对照实验（相对“静态基线”是否有可测改善）；
5. **发布**：新版本发布，版本化、可回滚、可定位一次回答所使用的组合。

**明确不做**：无审核的在线自动更新；把使用量当作学习成效；用“更流畅”冒充“更像名医”。

**激励设计（「待确认」）**：让贡献可见——导师可看到自己的纠正进入哪个版本；学员纠错被采纳可标记；反馈数量与质量进入团队看板。不设对外积分/排名，避免诱导错误数据。

**依赖资料与授权**：反馈数据授权与脱敏；评估集与回归集建设；版本与回滚机制。

**如何验证**：对照实验（有/无互动学习闭环）；回归测试通过率（退化率）；改进幅度与稳定性；错误归因率变化。

**创新点声明口径**：以“**可核验的互动学习闭环**”作为研究假设——互动反馈驱动的迭代能否在对照下提升教学效果、风格保真与问诊质量，且不引发退化。本文只定义机制与验证路径；结论留待实验。

**状态标注**：「需实验验证」。

## 五、辨证思维层（核心难题之二）：问诊 → 辨证 → 结论 → 处置建议

### 5.1 推理链定义

十问/四诊信息 → 证型假设（含支持与反对证据）→ 排除与取舍 → 结论与适用条件 → 处置建议（四类处方）。每一步可回看、可比较、可导出；保留分歧与矛盾，不把复杂辨证压成唯一线性答案（承 v1.3 §四.3、REQ-8.2.2）。

### 5.2 信息状态四态与缺失纪律

- 四态：**已确认 / 已否认 / 未问 / 无法判断**；“未提及”不得整理成“正常”（承 v1.3 §四.2）；
- 低质量图像、缺失脉象等不由模型自动补齐；缺口以“资料缺口提示”呈现（承 REQ-8.6.3、v1.3 §五.5）。

### 5.3 四种处方类型的输出与安全边界

| 类型 | 数字人输出形态 | 安全边界 | 验证方式 | 状态标注 |
| --- | --- | --- | --- | --- |
| 中药处方 | 方剂与加减、剂量区间的**参考建议**、煎服与禁忌提示；须医师确认 | 配伍禁忌、剂量上限、妊娠慎用等核查规则在环；不自动开方 | 对照药典/配伍规则自动核查 + 医师复核；用药安全率统计 | 建议生成「可工程交付」；面向患者形态「待确认」 |
| 针灸 | 穴位与手法的**教学性建议**（教学场景） | 不作为面向患者的远程操作指令；实际操作由执业者实施 | 专家审订；教学用途边界审查 | 教学场景「可工程交付」；患者场景「待确认」 |
| 推拿 | 手法、部位、频次的建议与禁忌提示 | 禁忌情形（外伤、骨质疏松等）提示线下就医 | 专家审订清单 + 场景脚本评估 | 同上 |
| 情绪/心理（情志） | 情志疏导、生活方式与调摄建议；心理危机转介 | 不替代精神心理医疗；自伤等危机信号立即转线下/热线 | 危机场景话术脚本 + 转介触发评估 | 转介话术「可工程交付」；疗效「需实验验证」 |

### 5.4 三来源身份（防冒名，承 v1.3 §五.6）

| 类型 | 界面标注 | 能说明什么 |
| --- | --- | --- |
| 本人原始口述 | 录制日期、原话片段、时间点 | 老师在该次记录中明确表达过的依据 |
| 导师审定整理 | 整理人、审定人、版本 | 经确认的教学表达，可能包含事后补充 |
| 模型教学解释 | 系统生成、引用材料、待审状态 | 帮助理解的解释草稿；**不得冒充前两类** |

生成式思维链可能给出貌似合理但不忠实的理由（相关研究见 v1.3 §五.6 及其引用）；面板展示可核验的教学依据与操作记录，不宣称揭示模型内部计算或名医完整内心。没有本人讲述之处，如实显示“原资料未记录这一原因”。

## 六、技术分层与研发取舍

### 6.1 三层 ↔ 参考技术路线（成熟组件优先）

| 层 | 目标 | 参考路线（开源栈见附录 B） | 取舍原则 |
| --- | --- | --- | --- |
| ① 形态神态 | 像、能听能说、可长时相处 | 图像说话头（SadTalker/Wav2Lip 离线；MuseTalk 实时）；高保真肖像动画（LivePortrait/Hallo 类）；三维重建（3DGS/NeRF/稀疏视图）；语音克隆（GPT-SoVITS/CosyVoice 类）；实时编排（pipecat/LiveKit/OpenAvatarChat 类） | 先集成成熟组件；目标设备延迟与稳定优先；自研只针对“素材稀缺与可控性”的明确缺口 |
| ② 辨证思维 | 会问、会辨、会给依据 | 大模型 + 专属检索（RAG）+ 知识图谱 + 输出与引用检查；教学证据单元组织 | 先建“专属资料检索 + 输出约束”基线；微调类方法后置，且先收集基线失败再选一种验证 |
| ③ 互动自进化 | 越用越会教 | 反馈队列 + 离线评估 + 回归测试 + 版本/回滚；对照实验框架 | 进化必须可核验、可回滚；不做在线自动更新 |

### 6.2 选题纪律（承《审阅与修改说明》）

- 连续预训练、全参微调、LoRA、知识图谱、偏好优化等**不同时列为必做**；先回答“为什么需要它”；
- 仅把姓名加入提示词、或仅用个人医案微调，都不足以说明名医经验被保留；
- 新增一种模态是否有用，用“删除该模态”的对照实验判断（承 v1.3 §六.5）。

### 6.3 与既有平台的衔接

- 四诊采集复用底座（舌 / 面 / 脉 / 闻模板与标注能力）；脉象与闻诊的原始信号、设备参数、专家标签与独立验证满足条件后，才进入联合教学解释（承 v1.3 §四.5、§六.5）；
- 数字人任务与底座分类/检测任务分线管理（承 REQ-8.5.4）。

## 七、边界与合规（承诺性边界）

1. **医疗与监管**：AI 辅助定位；不替代医师；不向患者自动处方；危重、超范围、资料不足场景明确拒绝或建议线下就医（《互联网诊疗监管细则（试行）》）。
2. **AI 标识**：数字人界面始终说明其为 AI 生成或模拟；对外传播的合成音视频保留显式与隐式标识（《人工智能生成合成内容标识办法》，2025 年生效）。
3. **授权**：名医形象、声音、医案、讲课视频、学术资料分别登记授权范围与期限；患者病历使用依据另行确认（知情同意）。
4. **隐私**：《个人信息保护法》口径——去标识化不等于不可再识别；“已脱敏”不自动等于可公开、可训练；资料撤回时，处理检索副本、媒体、已发布内容及关联模型版本。
5. **故障降级**：数字人故障不阻断教学与管理流程，降级到文本、原始资料或已审定课程。
6. **责任**：临床辅助相关功能的责任、验证与适用要求单列；不以“仅供参考”替代功能边界。

## 八、分期与验收

### 8.1 分期路线（由浅入深）

| 阶段 | 形态 | 能力（本阶段交付） | 进入条件 | 完成标准 |
| --- | --- | --- | --- | --- |
| A 样机期 | L1 | 单名医教学闭环：医案讲解 + 依据面板 + 追问；训练协议试运行 | 授权素材充足；审订人到位；教学任务选定 | 3 分钟教学演示 + 训练协议试运行 4 周记录 + 风格保真首评记录 |
| B 强化期 | L2 | 模拟问诊模式；辅助问诊（院内，医师在环）；四类处方教学性建议 | A 完成；设备与素材确定；合规评估通过 | 端到端演示（讲—问—答—依据）+ 问诊完整度与遗漏指标记录 + 部署适配报告 |
| C 拓展期 | L2+（可含 L3 选项） | 患者/健康人群试点（合规形态下）；互动自进化闭环上线（离线迭代） | B 完成；对照实验设计冻结；合规/伦理/授权到位 | 对照实验报告（有/无互动学习）；回归通过率达标；版本回滚演练完成 |

**数量口径**：本文按“先一名名医样机、机制可复制多名”定义；多名交付的数量与范围以核实后的项目范围为准（承 v1.3 §一.2、DEC-11）。

### 8.2 指标纪律（必须记录的证据 vs 不能替代它的指标）

| 对象 | 必须记录的证据 | 不能替代它的指标 |
| --- | --- | --- |
| 知识与解释 | 独立题集、引用支持、错误归因、拒答与覆盖率 | 回答流畅、模型自评分 |
| 名医特色 | 条件相近病例、匿名盲评、审定依据 | 姓名、口头禅、药物词重叠 |
| 问诊能力 | 关键遗漏、重复追问、矛盾处理、提问预算 | 对话轮次、“完整度”自述 |
| 学习成效 | 前测/后测、新病例迁移、评分分歧 | 满意度、访问量 |
| 形象语音 | 授权评价、术语错误、口型同步、打断与延迟 | 一段精修视频 |
| 自进化 | 对照实验、回归通过率、改进稳定性 | 使用量、更新次数 |

**注意**：形象逼真与问答流畅只证明部分体验质量；与“经验保留、教学有效”分开报告。
