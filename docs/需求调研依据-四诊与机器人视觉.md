# 需求调研依据：四诊标签与机器人视觉

日期：2026-09-07。用途：支持《需求规格说明书-v2.0-讨论稿》的第二轮修订。下文区分用户决定、已有方案、公开研究与本次工程建议；论文中的采集方法不能证明教授手上的实际数据格式。

## 1. 用户补充决定

- 使用人数：**四人**。
- 用户认为不需要标注提交、专家复核流程：首期按**不设独立提交与复核环节**设计，复核不作为训练门槛。
- 机器人任务参考 `D:/ProgramData/xmu/RAG-test/wiki/research/carri-flex-eye-vision-design.md`。
- 四诊真实标签和数据格式尚不清楚，用户要求先调研。
- 用户尚未回答质量过滤具体含义；不能把“无需复核”解读为“不做数据质量标记”。

方案中的“±5mm”等数值是历史目标，缺少统一的测量对象、误差定义、距离范围及独立真值时不能直接转为承诺。新要求须分别评价框检测、目标选择、相机系定位、基座系定位与机器人执行，不能用执行成功率代替视觉精度。

**工程结论**：平台保留四诊模板，同时新增机器人模板；共用数据版本、训练调度、模型登记和导出能力，分别使用标签字典、标注工具与训练器。机器人 P0 必须支持检测框，ResNet 分类骨干不能独自承担框检测。YOLO 系列可以作为方案候选，具体版本/许可证/导出兼容性在选型时核对；不在本轮锁死。

## 3. 四诊标签与模态：调研结论

### 3.1 舌象允许多个属性同时存在

原始研究明确展示裂纹、齿痕、腻苔等多个特征在同一舌图共存，因此当前“舌类下只能选择一个标签”不足以表达此类数据。[S1](https://pmc.ncbi.nlm.nih.gov/articles/PMC9536899/)

另一项标准化舌图数据库研究分别评价舌体颜色、大小、湿润程度、齿痕、裂纹、苔厚及苔色等项目。这支持“按属性建模”的设计，但该研究的分类规范不是本项目已经批准的标签标准。[S2](https://www.frontiersin.org/journals/medical-technology/articles/10.3389/fmedt.2021.760542/full)

**建议草案**：

| 属性组 | 建议形式 | 示例和边界 |
| --- | --- | --- |
| 舌体颜色 | 独立分类属性 | 淡红/红等仅为示例，类别表待样本核对 |
| 舌苔颜色 | 独立分类属性 | 白/黄等；允许与舌体颜色同时标注 |
| 舌苔厚薄 | 独立有序属性 | 薄/厚等；程度标准待定义 |
| 齿痕、裂纹 | 各自独立属性 | 存在/不存在/无法判断；可以同时存在 |
| 其他形态或苔质 | 可扩展属性 | 不把不同属性的标签混在一个互斥列表 |

同一个属性内部也不能未经定义就强制互斥；有混合颜色或局部差异时，可采用“主导颜色”“多选”或“分区”方案，必须在标注指南中明确。未知不等于不存在，未观察不等于正常。模型输出应按任务 schema 构建，不能固定为四个诊法各一个 softmax。

### 3.2 面象不能直接复制舌象标签，也不能武断宣布全部多选

面色研究使用额头、面颊、鼻、下巴、嘴唇等区域的颜色特征，并讨论颜色校正。因此应保留区域和采集光照信息，避免把图像颜色变化直接认定为业务标签变化。[S3](https://pmc.ncbi.nlm.nih.gov/articles/PMC5664382/)

工程上建议先支持“整体面色分类 + 可扩展区域属性”。现有证据不说明教授要求的“红润/苍白/萎黄”能否多选，也不支持由此自动推断疾病；真实标签表仍待任务资料或样例确定。

### 3.3 脉诊通常涉及随时间变化的传感器信号

脉诊采集研究使用触觉传感器在寸、关、尺位置采集，并研究不同按压深度下的信号。这支持将脉搏数据建模为带采集位置/压力等元数据的时序信号，而不是默认一张普通 RGB 图片。[S4](https://www.sciencedirect.com/science/article/pii/S0010482513000127)

建议保留原始波形、采样率、单位、通道、时长和传感器信息；如果实际交付只有波形截图，登记为“波形图像”，不能宣称已保留原始信号。原始格式可能是 CSV、二进制或设备专有文件，公开研究不能替项目确定扩展名。

### 3.4 声音应优先保存原始音频

闻诊信号研究描述通过麦克风及 A/D 设备录制声音后分析信号。这支持音频作为原始资产，频谱图作为带转换配置的派生产物，而非只保存截图。[S5](https://pmc.ncbi.nlm.nih.gov/articles/PMC3369240/)

建议登记采样率、声道、时长、录音设备和噪声质量；首期若无实际音频需求，保留模板和导入契约，播放/波形编辑/音频训练单独排期。不能从舌或面照片生成有意义的声音监督。

## 4. 四人协作且无复核流程的落地

- 四个独立账号，建议管理员/成员两级，不引入多级审批、复杂组织结构。
- 默认状态：未标注 → 标注中 → 已标注；保存满足任务 schema 的有效标签后自动更新状态，不要求另点“提交审核”。
- 训练准入：质量合格 + 对应任务标签有效 + 无未解决冲突；不要求专家复核通过。部分缺失属性按掩码处理。
- 四人同时改不同样本应成功；同时改同一样本由 revision 冲突检测保护，展示修改人和时间。不会因“没有审核”而取消编辑审计。
- 预测建议须由使用者采纳或修改后才成为人工标签；这属于标注操作，不是独立专家复核环节。
- 标签定义仍需一份一致的指南；教授只需对任务范围和标签含义作业务确认，不必逐张审批。未经专家复核的数据如实标记，不包装成专家金标准。

## 5. RGB-D 与坐标的必要约束

RealSense 官方文档区分像素坐标、相机三维坐标、内参与流间外参；像素反投影需要对应深度和相机内参，深度值须正确换算为米。[S6](https://github.com/realsenseai/librealsense/wiki/Projection-in-RealSense-SDK-2.0)

据此提出以下工程要求：保留原始 RGB、深度、时间戳、流间对齐关系、depth_scale、内参/畸变和标定版本；深度可视化图不能代替测量深度。零深度/无效深度不输出可执行目标。腕装相机转基座坐标时须关联采集时刻的机器人位姿与手眼标定，不把相机移动后的固定单位阵当有效标定。
